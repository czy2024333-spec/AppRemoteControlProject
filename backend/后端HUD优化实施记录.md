# 后端 HUD 优化实施记录

2026-11-12 · 基线为本机已核对的 GitHub 后端 v0.9，源码快照来自 `6b1f0de`。GitHub 比较显示该基线的后端包含 `ebb2ed3` 日志修复。本轮在独立目录实施。

## 用户确认

- 审计故障沿用现有保护策略。C8 的降级继续飞行和审计队列分级列入后续讨论。
- 运动报文过期沿用 `PROTECTED`，心跳不续期运动。
- 视频字段沿用 `NOT_CONNECTED`，APP 的实际播放状态由播放器报告。

## 已优化的部分

| 方案 | 已落地的改动 |
| --- | --- |
| C1、C2 | 位置、速度、姿态、角速度带上 `age_ms` 和 `reason`。本地测量按三个采样周期判过期，20 Hz 时是 150 ms。样本序号沿用原字段。 |
| C3 | 统一状态补上保护原因、恢复窗口、目标航向和仿真环境。阻塞项由核心给出，包含 `ALTITUDE`、`RADIUS`、`SPEED`。归中确认由实际操作提供，边界阻塞项只描述可测的动力学条件。 |
| C4 | 补上 `control.active`、`awaiting_neutral` 和 `last_applied`，最近应用序号只记录执行成功的运动，切换轮次时清除。 |
| C5、C6 | 视频沿用原取值。服务退化返回明确分类，保留原始错误码。对于运动报文，`RETRY_LATER` 表示等服务恢复后由用户发起新意图。 |
| C7 | 仿真线程一次发布完整状态，内部读取无需持有发布锁。配置按版本复用，统一 SSE 帧由每个服务的发布线程共享转换。逐机旧接口继续提供 `instance_config`。 |
| C8 | 维持审计故障保护。修复了飞机已锁存其他保护时，审计故障反复刷新轮次的问题。 |
| C9 | 独立模式 SSE 由共享发布线程收集，目标 25 Hz。无状态变化发注释心跳。用 `Last-Event-ID` 恢复最近 50 帧内的状态，过期或服务重启后发送重同步标志与最新帧。另提供可选 `focus`。 |
| C10、C11 | 身份与可写设备继续从 `capabilities` 获取。设备目录公开配置来源，健康接口公开实际步频、步长抖动 p99、采样数及迟于计划至少一个步长的次数。 |

## 与 GitHub APP 的对照

已读取 [PR #4](https://github.com/czy2024333-spec/AppRemoteControlProject/pull/4) 的 `4dd149a`。横屏 HUD 使用逐机 `RotorState` 的 `environment`、`boundary_recovery` 等原字段。总览通过 `UnifiedRepository` 读取全机统一状态，当前仍以整机新鲜度为主。客户端允许未知 JSON 键，SSE 只处理带 `data:` 的行。旧请求继续得到全机完整帧。

请求 `GET /api/v1/events?focus=sim-drone-2` 时，目标机每帧返回完整状态，其他成员约 10 Hz 返回位置、实际偏航、模式、新鲜度。仅在 `peers_included=true` 时更新僚机，其他帧应保留各自上一份样本，并按时间判过期。历史帧带 `replayed=true`，可用于补轨迹。连接失效或恢复后仍由当前状态和控制流程判定能否操纵。偏航零点为世界 X 正向，绕 Z 正轴逆时针为正。

旧客户端继续使用原路径。白名单网页可预检并发送 `Last-Event-ID`，连接与每次 GET 都沿用现有鉴权。

## 实施过程中发现并修复的问题

- 首轮后端回归的 124 项中有 1 项失败。新增 SSE `id` 最初放在首行，旧测试工具按 `event`、`data` 的顺序读取。将 `id` 移到事件结束前后，124 项回归全部通过。
- 动力学 27 项首轮运行通过，其中 1 项旧实验输出检查按原条件跳过。
- 首轮 60 秒新版 SSE 实收 21.10 Hz，基线约 25 Hz。修正共享发布线程按计划时间推进后，复测四路各实收 1500 帧，即 25.00 Hz。

## 第一轮本机单次对照

相同测试场景各跑 60 秒。三路操纵和四路观察，三台实例各 50 Hz 步进。p99 为实际步进间隔相对 20 ms 的绝对偏差。

| 指标 | 基线 | 优化版 |
| --- | ---: | ---: |
| 三路控制回执 P95 | 19.49–20.22 ms | 17.64–18.56 ms |
| 四路 SSE 实收 | 24.98–25.02 Hz | 25.00 Hz |
| 1 号机步长抖动 p99 | 15.47 ms | 15.21 ms |
| 2 号机步长抖动 p99 | 16.69 ms | 15.96 ms |
| 3 号机步长抖动 p99 | 17.67 ms | 16.54 ms |

优化版 3573 条运动全部确认，压测期间无失联、非预期保护或 SSE 错误。第一轮单次数据不足以判断去锁对抖动的影响，复审另对等待方式做了重复对照。

## 第一轮后端回归

`run_checks.py` 的后端 125 项全部通过，包括三机审计保护、输入过期、SSE 兼容、短时续传、注释心跳、焦点分流、续传请求头白名单与配置来源。动力学 26 项通过，1 项旧实验输出检查按原条件跳过。第一轮完整记录保存在本机交付目录的 `results/checks-initial-hud/`。

## 复审后的改动和问题

- Windows 11、CPython 3.13.14 下确认 2 ms 的 `Event.wait()` 明显超时。改用 `time.sleep()` 短等待，三次对照中三机抖动 p99 的中位数从 15.12–16.81 ms 降到 0.96–1.06 ms，改后控制回执 p95 为 4.70–5.00 ms，四端 SSE 实收 24.98–25.02 Hz。逐机最小值／中位数／最大值见 [后端架构逻辑说明](后端架构逻辑说明.md)。
- SSE 发布线程异常或卡住时结束订阅，健康接口暴露原因。PR #4 已有独立的 500 ms 新状态超时，保留注释心跳。`capabilities` 新增五项布尔标志，契约仍为 1.0。
- 新回归确认 STOP 轮次、模式和按 ID 查询的回执，统一 `protection.recovery` 和旧逐机 `boundary_recovery` 在同一发布序号上相等。跨动作复用同一离散 ID 曾错误返回上一个动作的回执，已加入动作路径校验。审计恢复需要重启和主动建立新会话。后端 131 项通过，动力学 26 项通过、1 项按条件跳过。[后端与动力学回归摘要](../docs/validation/后端HUD_20261112_验证摘要.json)
- PR #4 固定版本的 25 项 JVM 回归通过，其中两项新增用例验证单机和总览收到注释心跳时仍按新状态时间过期，以及新增能力标志的解码。
- UE 和旧联调页的 SSE 解析不依赖 `id` 行位置。UE 健康检查所需的 `boot_id` 已补齐。UE 的 `EventsPath` 和旧联调页仍须按独立模式选择相应路径。PR #4 后续需验证重连首帧超时、接入新状态字段，并完成手机局域网刷新和延迟验收。

## 运行

在本目录用 `drone-sim-backend` 解释器运行以下命令。

```powershell
python run_backend.py --doctor
python run_backend.py --mode independent --host 0.0.0.0 --port 8765
python run_checks.py
```

六份 HUD 样例在 `契约样例_v0.9/hud/`。第一轮压测原始汇总保存在本机交付目录的 `results/baseline-60s/summary.json` 和 `results/optimized-cadence-60s/summary.json`。
