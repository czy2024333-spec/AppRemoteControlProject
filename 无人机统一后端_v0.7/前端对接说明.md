# 三来源统一接口：CTL基线与v0.5补充

本文件保留CTL基础时序；v0.5的语音请求必须增加recognized与confidence，推荐新端点/api/voice-result。指环事件、确认及硬件接入见 **IN接口补充说明.md**。下文旧版/api/voice字段示例不能单独直接使用。

## 控制流程

```text
APP、指环、语音分别建立来源会话
    ↓
用户在APP选择目标通路 → POST /api/switch
    ↓
清除旧输入，mode=HOLD，pending_source=目标，selected_source=null
    ↓
目标来源读取新状态，发送新鲜中立采样 → POST /api/neutral
    ↓
selected_source=目标，仍保持HOLD；用户再次操纵才开始运动
```

APP是操作端，有切换、恢复、配置及跨来源取消/查询权限；指环和语音只能在被选中后输入。停止、保护优先于一般报文。source身份由Token确定，请求体自报source/role不能获得权限。适用于一台仿真设备`sim-drone-1`，同一来源只允许一个当前会话，不提供多账号登录和多飞机调度。

## 来源鉴权

| 来源 | 默认局域网联调Token | 能力 |
|---|---|---|
| APP | demo-app-token-2026 | 连续四轴、选择来源、配置、恢复、查询/取消 |
| 指环 | demo-ring-token-2026 | 连续四轴、停止、保护、断连报告、自身命令查询 |
| 语音 | demo-voice-token-2026 | 八个限时离散动作、停止、保护、断连报告、自身命令查询/取消 |

每个请求带`Authorization: Bearer 对应Token`；POST带`Content-Type: application/json`。可用--app-token/--ring-token/--voice-token分别替换，至少16位且互不相同。只给相应适配器提供对应Token。该鉴权用于可信局域网联调，不替代生产用户权限系统。

## 接口与公共字段

| 方法/路径 | 用途 |
|---|---|
| POST /api/session `{}` | 建立来源会话；返回session_id、control_epoch、device_id；重建会话撤销该来源旧输入 |
| GET /api/state | 状态、选中/待切换/实际执行来源、配置、能力和最近事件 |
| GET /api/events | SSE状态推送，目标25Hz；原生客户端流式读取 |
| POST /api/heartbeat | 当前来源连接心跳；不更新运动TTL、不恢复运动 |
| POST /api/switch | APP主动切换，等待目标来源中立 |
| POST /api/adaptive-switch | 预留策略入口，与switch相同权限、用户主动确认和归中校验 |
| POST /api/neutral | 目标来源提交实际归中值 |
| POST /api/input | APP/指环归一化四轴输入，应用死区/灵敏度/映射 |
| POST /api/control | APP/指环已经转换好的物理速度输入 |
| POST /api/voice | 已识别语音的限时动作，不接收音频或自然语言 |
| POST /api/stop /api/protect | 停止保持 / 锁存保护；任何已建立会话的来源均可请求 |
| POST /api/resume | APP确认全部来源中立后解除保护；之后必须重新switch+neutral |
| POST /api/cancel | 取消待归中切换或正在执行的语音动作 |
| POST /api/disconnect | 上报退出、外设断连、输入/控制权失效 |
| POST /api/config | APP受限策略更新，仅HOLD且无待切换来源时允许 |
| GET /api/commands/{source}/{command_id} | 查询本会话离散命令；APP可跨来源查询 |

除了建立会话，所有POST均需要以下公共字段（保护和心跳不要求epoch匹配，仍校验其他字段）：

```json
{
  "device_id": "sim-drone-1",
  "session_id": "来源建立会话后收到的ID",
  "control_epoch": "最新控制轮次",
  "command_sequence": 0,
  "ttl_ms": 500,
  "sent_at_ms": 1790000000000
}
```

sent_at_ms必须每次首次发出时填写当前Unix毫秒，示例数字不可直接使用；手机和电脑时钟同步。TTL扣除报文年龄和排队耗时，范围(0,当前配置input_ttl_ms]，最大500ms，时钟超前超过50ms拒绝。序号按来源会话递增，心跳也占用序号；同一来源必须用单一串行发送队列，不能多个异步协程各自维护序号。

离散POST另需`command_id`，1–64位ASCII字母数字、-或_，推荐UUID。连续/input、/control、/heartbeat不需要命令ID。

## 切换与中立握手

APP的switch在公共字段基础上加：

```json
{"command_id":"switch-001","target_source":"ring","user_initiated":true}
```

switch返回新的control_epoch，状态为WAITING_NEUTRAL。目标来源读取状态后更新epoch，提交neutral：

```json
{"command_id":"neutral-001","axes":[0.0,0.0,0.0,0.0]}
```

axes必须来自目标来源当前新鲜采样，顺序前后、左右、升降、偏航，绝对值均落在配置deadzone内。指环不能在旧手势仍持续时伪造零值；语音进入通路前必须清空未执行的识别结果，再由适配器报告中立。5秒没有完成归中会NEUTRAL_TIMEOUT保护，switch状态TIMED_OUT。归中成功只到HOLD，后续新操作才允许运动。

状态显示：selected_source是用户已启用通路；pending_source是等待归中的通路；active_source是当前真正下发运动的来源。不要仅根据界面按钮更新来源标识，以服务返回为准。

## 连续操纵

推荐/input，额外字段：

```json
{"intent_sequence":0,"frame":"heading","axes":[0.6,0.0,0.0,0.0]}
```

axes各分量[-1,1]，正值分别前进、左移、上升、左转。右移/右转需负号，屏幕坐标方向由前端转换。死区之外重映射到[0,1]，再乘灵敏度；水平二维合量归一化，避免斜向超速。

如果适配器已经输出物理量，可使用/control，额外字段：

```json
{"intent_sequence":0,"frame":"heading","vx_m_s":0.3,"vy_m_s":0.0,"vz_m_s":0.0,"yaw_rate_rad_s":0.1}
```

物理量接口仍受配置速度限制，但不重复应用死区与灵敏度。默认水平合速度≤0.5m/s、竖直≤0.5m/s、偏航≤0.5rad/s。frame=world是固定局部世界坐标；heading按本次接受指令时机头偏航旋转水平分量，不随横滚/俯仰倾斜。

intent_sequence代表一次新的用户操纵事件（触摸按下、指环新手势或新语音），每次事件递增，同一次操纵持续刷新保持不变。停止、切换、保护后旧事件被撤销，禁止刷新epoch并自动给旧输入增加intent来续控。

连续运动建议每50ms发送最新四轴快照（20Hz），不积压历史输入，两摇杆合并为一条。全部归中时发stop；只松开一个摇杆时发送另外摇杆与归中轴合并的新值。

## 语音与幂等

/voice增加：

```json
{"command_id":"voice-001","intent_sequence":0,"frame":"heading","action":"forward","duration_ms":1000}
```

允许动作forward/backward/left/right/up/down/turn_left/turn_right；执行时长100–5000ms；默认速度为配置上限的60%。语音识别由前端负责，识别完成时间才算有效命令生成时刻。执行期间只发heartbeat，不要重复生成语音运动命令续时。

状态：WAITING_NEUTRAL、EXECUTING、COMPLETED、CANCELLED、TIMED_OUT。HTTP 200表示命令已校验并应用/安排，不代表限时动作已经完成；使用查询接口查看最终状态。

同一session+command_id的重试，保持原动作、原序号、原epoch等内容一致；可以刷新sent_at_ms/ttl_ms。后端返回已有状态，不重复动作、不延长时长。换动作复用ID返回COMMAND_ID_REUSED。重建会话/服务重启后旧session无效，不能跨会话重试旧运动。每会话最多1024个离散记录，满后停止并重建会话，不淘汰历史后再次执行旧ID。

APP取消语音：/cancel加`command_id`（本次取消自己的ID）、`target_source:"voice"`、`target_command_id:"voice-001"`。取消只停止目标正在执行的动作，不会重置其他已完成任务。取消待归中的switch也使用该接口。

## 失效与恢复

当前选中来源和APP监督端都要持续心跳，建议100ms一次；若调整TTL上限，心跳周期应小于该上限的三分之一。运动指令自身会刷新该来源连接存活，但APP监督心跳不能省略（APP自己操纵时运动请求可承担存活刷新）。心跳不延长运动TTL或语音duration。

没有新运动报文达到TTL：INPUT_TIMEOUT。选中指环心跳丢失：PERIPHERAL_DISCONNECTED；语音连接丢失：NETWORK_INTERRUPTED；APP监督端丢失：CONTROL_LOST。当前有效来源提交非法新运动参数：INPUT_INVALID保护；旧序号/旧轮次只拒绝，不干扰新操作。服务卡顿：SCHEDULER_STALL。都锁存保护并清除控制通路。

前端检测生命周期/蓝牙/网络事件时主动发/disconnect，增加唯一command_id和reason，允许APP_EXIT、PERIPHERAL_DISCONNECTED、NETWORK_INTERRUPTED、INPUT_INVALID、CONTROL_LOST。若断网无法报告，后端超时兜底；原因只能记为检测到的超时，不能凭空判断真实物理故障。

恢复流程：清空全部来源旧输入→APP以新epoch请求/resume（command_id、neutral_confirmed:true）→重新switch→目标实际neutral→新的操纵。重连先建立新来源会话，禁止恢复失效前的运动。

/stop保持当前启用通路，但撤销旧操纵，后续需要新的用户事件；等待归中期间stop会取消切换。/protect锁存保护并清除通路，不依赖当前epoch匹配，仍需新鲜合法序号与命令ID。二者制动都不瞬移、不关电机。

## 配置管理

默认配置在control_config.json；CLI --config指定另一个完整配置文件。运行时/config加command_id、config_version和patch：

```json
{"command_id":"config-001","config_version":1,"patch":{"sensitivity":0.6,"deadzone":0.1}}
```

可修改字段：sensitivity [0.1,1]；deadzone [0,0.4]；水平/竖直/偏航上限各[0.05,0.5]；input_ttl_ms [50,500]；sources_enabled完整三来源bool；input_mapping完整app/ring四轴带符号排列，如[1,-2,3,-4]；voice_mapping为八个白名单动作之间的映射。嵌套对象更新时传完整对象。

配置只能在HOLD且没有待切换时更新，需要匹配版本；保存到配置文件后再提交内存，重启读取保存值。更新撤销通路，必须重新switch+neutral。不允许修改质量、惯量、角色权限、核心硬限制和设备ID。

## 状态推送与坐标

GET /api/events带来源Token，响应text/event-stream；解析`event: state`和`data: {状态JSON}`，每40ms最多发布一份新步号状态，目标25Hz。Android需后台线程流式解析，UI使用最新状态、不排队重画旧帧。若用轮询应间隔≤50ms，并实测是否满足20Hz。SSE不能代替POST心跳。

位置position_m为米，速度velocity_m_s为m/s，quaternion_xyzw顺序x,y,z,w，机体到世界旋转，世界X前/Y左/Z上。状态来源simulation_truth，不是GNSS测量。前端不同坐标系需同时转换位置和姿态。

ack.status=APPLIED，server_received_at_ms为服务完整请求入队时刻，confirmed_at_ms为应用后确认构造时刻，queue_and_apply_ms为服务侧排队加应用耗时。前端生成指令到收到确认需用自身单调时钟统计；不能用queue_and_apply_ms冒充端到端P95。

本机演示测量包括参考客户端HTTP收发与状态接收；真实APP刷新频率还需在UI实际应用新状态时打点，不得以收到SSE就认定画面达到20Hz。

## 错误处理

400字段/范围/配置错误；401来源鉴权失败；403权限/能力/禁用通路；404未知路径/命令；409轮次、序号、通路、模式或幂等冲突；503队列/历史/服务不可用。失败包含error_code。任何运动失败先暂停输入流并读状态，禁止自动续控或自动切换。只对离散动作使用同ID幂等查询/重试；连续指令不重放。

原生APP和适配器局域网对接；本服务没有浏览器CORS或音频识别功能。若指环通过手机蓝牙接入，手机同时承担三种来源的适配角色，使用独立来源会话与序号即可，不必让指环硬件自己连接HTTP。
