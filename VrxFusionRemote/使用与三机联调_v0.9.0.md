# v0.9.0 使用与三机联调

本版只升级 Android 前端，配合用户提供的《无人机独立操控后端_v0.9.zip》。同一个 APP、同一个后端地址，三台手机分别操纵自己的飞机；每端均能观察三架。位置来自后端仿真，单位为米。

## 1. 安装与启动

1. 手机安装 `旋翼遥控APP-v0.9.0-覆盖更新.apk`，直接覆盖现有“旋翼遥控·优化版”。包名及签名沿用优化版，版本号 900 / 0.9.0，无需卸载。
2. 电脑解压后端 v0.9，用 VS Code 打开**能看到 run_backend.py 的目录**，选择已安装依赖的 `rotorpy-day1` Python 解释器，在该目录打开终端。执行：

```powershell
python run_backend.py --mode independent --doctor
python run_backend.py --mode independent --host 0.0.0.0 --port 8765
```

自检失败时先按后端说明修复环境。不要在 `C:\Users\24107` 空目录直接运行脚本；不要同时启动另一份占用 8765 的旧服务。APP 本次连接的是 HTTP/SSE 服务，无需启动源码中历史 `server/` WebSocket 服务。

3. 电脑执行 `ipconfig`，找到当前 Wi-Fi/以太网的 IPv4。手机与电脑连同一局域网，APP 地址填 `http://电脑IPv4:8765`，例如 `http://192.168.1.100:8765`。手机不能填 localhost、127.0.0.1 或 0.0.0.0。
4. 若连接失败，检查地址、独立模式、Windows 防火墙的专用网络 Python 入站权限，以及路由器是否开启客户端隔离。原生 Android APP 不需要网页 CORS 白名单。

## 2. 给每台手机选择身份

进入首页“独立操纵”，点右上角齿轮，在连接设置中选择预设并连接。预设自动填写后端样例 Token，无需手输。

| 手机 / 用途 | APP 预设 | 后端样例 Token | 可操纵飞机 |
|---|---|---|---|
| 手机 A | 操纵端1 | demo-pilot-1-token-2026 | sim-drone-1 |
| 手机 B | 操纵端2 | demo-pilot-2-token-2026 | sim-drone-2 |
| 手机 C | 操纵端3 | demo-pilot-3-token-2026 | sim-drone-3 |
| 手机 D，可选 | 观察端 | demo-observer-token-2026 | 无，三机只读 |

这是后端提供的**开发联调凭据**，不等于正式用户登录或管理员权限。若后端负责人改过凭据，填写新 Token，且只填本身、不加 `Bearer`。实际绑定以后端返回的 `self_device_id` 和写入权限为准，界面预设名称不能赋予权限。自定义 Token 不保存到磁盘；只保存公开预设的选择编号。

连接成功只是查看状态。关闭设置，检查操纵页左上角的飞机编号，摇杆归中，再点“申请控制”。看到“已接管 / 控制就绪”后才推杆。没有主动申请时不会自动接管。

## 3. 操纵与观察

- 每台操纵端只能给自己的飞机发送控制、心跳、停止、保护及解除保护请求。其他飞机的标记只供观察，点击地图不会更改控制目标。
- 右上角显示三机编号和 XYZ 坐标，本机以黄色外圈及“本机”文字突出。上方为 +X，左侧为 +Y，高度为 +Z，坐标单位米。
- 地图默认涵盖全机位置；单点切换为以本机当前位置为中心的近景，再点回总览。近景中超出视野的他机用边缘空心标记及省略号提示，坐标行仍保留真实位置。
- 保留全屏视频背景、姿态仪、双摇杆、透明度设置及醒目的停止/保护提示。地图是遥测示意，不代表已接入真实地图或 GNSS。
- 首页“三机只读总览”连接相同地址，可选择观察端。地图下紧凑列出三机坐标、运行模式及实时/过期状态，下方可滚动查看速度、数据质量、任务、视频和告警。分组筛选只改变观察范围，不申请控制。
- 状态超过新鲜度阈值或成员失效时，显示过期、灰色历史标记或坐标横线；不把历史位置当作实时数据。其他成员失效不会仅因其状态失效撤销本机有效控制。

一台手机可以顺序控制三架：先松杆，打开连接设置点“断开连接 / 修改地址”，选择另一操纵端，重新连接并确认编号，再主动申请。前端先尝试停止并释放旧飞机；释放未确认时会提示，阻止直接更换会话。断线、重连和切换均不会恢复先前运动。**同时独立操纵三架需要三端各持一份有效会话，一根摇杆不广播控制三架。**

## 4. 推荐现场测试顺序

| 步骤 | 操作 | 应看到的结果 |
|---|---|---|
| 只读基线 | 四端连接，暂不申请控制 | 均显示三机；观察端没有有效控制能力；飞机保持初始状态 |
| 单机隔离 | 端1主动申请并轻推右杆，端2/3不接管 | 仅1号移动；四端均看到1号位置变化 |
| 三机同时 | 三操纵端各自申请，分开轻推杆 | 各自飞机分别响应；每端地图同时显示三机 |
| 松杆 | 只松开端2 | 2号悬停；端1/3仍按各自输入响应 |
| 单机保护 | 端1点击保护 | 只保护1号；端2/3继续；只读页看到1号保护状态 |
| 解除保护 | 端1归中，按界面主动解除并重新申请 | 满足后端校验才恢复，旧运动不重放 |
| 单端退出 | 退出端1或断开端1网络 | 1号按后端保护策略停止/悬停；另外两端继续；失效原因可查 |
| 单机换端 | 仅一台手机断开后从端1换端3 | 旧会话先释放，新端只观察，主动申请后仅控制3号 |
| 只读核对 | 观察端看三机位置、模式和告警 | 与三操纵端一致，无接管/广播运动；切组不影响操纵 |

首次按小幅度、短时间测试，避免越过仿真边界。如果“保护”不能解除，查看实际告警与后端边界条件；前端不会绕过安全校验。三机共享观察不包含自主编队、碰撞规避或任务分配。

## 5. 打开源码

Android Studio 打开包内 `VrxFusionRemote-v0.7` 目录（目录名保留以延续原工程，实际版本为 0.9.0），Gradle JDK 选 17，安装 Android SDK 34 / Build Tools 34.0.0。最低 Android 10。源码不含个人 SDK 路径、签名私钥、完整 Python 运行环境或离线 Gradle 缓存。

交付 APK 已与旧优化版校验为同一签名。源码自行编译若使用另一签名，不能覆盖当前手机应用；请用团队原有签名构建覆盖包。不要把本次发布理解为要求卸载旧 APP。

本机完成了接口回归、原生 UI 检查和 60 秒三机/四端联调；指定手机上的局域网延迟、实际画面、外设及 4 小时稳定性仍需现场测试，详见本版验证报告。
