# 日志接口修复 · 2026-11-05

基于 role-b-logs-export-1119 的 3525536；当前日志接口仍为 HTTP GET，控制权限、TTL、运动指令和前端代码未改变。日志能力可通过 capabilities.routes.logs / logs_export 发现。

## 有界处理

原始 fleet_events.jsonl 和各成员 control_events.jsonl 是证据源。后台单线程每周期最多读取约512 KiB、处理512行，约50 ms让出一次；索引为本次进程可重建的 SQLite/WAL 文件，不是新的审计来源。首次大历史日志建立索引时返回503 LOG_INDEX_BUILDING，查询不临时全扫原始文件。索引假定原始文件仅追加；检测到截断/替换时重建并使旧快照失效。原地等长修改历史内容需要重启服务重建索引。

SQL 查询有0.5 s预算，分页最多2000条、事件载荷约2 MiB，offset最大100000；超出范围应按设备/时间缩小查询。单次导出最多16 MiB，生成预算5 s；先生成有界临时文件，再返回Content-Length并按64 KiB发送，下载总预算30 s。日志查询/导出单次只执行一个操作，繁忙时503 LOG_BUSY；状态、SSE和运动接口不使用此操作锁。SQLite原生缓存每连接配置约2 MiB。

索引磁盘占用随历史记录增长，不等于内存全量载入；本次没有引入原始审计日志的轮转/保留策略，长期磁盘容量仍需部署配置。异常退出可能留下本次临时索引文件，清理时须辨认原始日志，不能删除证据源。

## 查询

GET `/api/v1/logs` 支持 device_id、event、since_ms、until_ms、offset、limit；时间为Unix毫秒，范围含端点，排序为服务端时间与内部行ID。鉴权沿用Bearer Token；观察端可读全机日志，但仍不可控制飞机。

响应保留 events/total/offset/limit/files/filters/viewer 等已有字段，增加：

- snapshot：当前索引代次与行ID上界；下一页带同一snapshot，并使用next_offset，避免并发追加导致重复/遗漏。
- has_more / next_offset：受条数和字节预算共同控制。最后一页next_offset为null。
- index.indexed_at_ms / caught_up：索引时刻与本批文件快照是否追平；后台索引和审计刷新均可能有延迟，不能把它当实时控制状态。
- integrity.invalid_rows / pending_tail / complete：损坏行数、未写完尾行数、当前批次完整性。complete=false时应显示提示。
- files[].invalid_samples：每文件最多20个样本，含line、byte_offset和code；不会回显原始行或Token。

错误类型的时间戳、NaN/Infinity、非法UTF-8、超过64 KiB的单行和坏JSON均被计数并定位，不会误报为用户参数错误。有损坏行时默认查询也返回409 LOG_DATA_CORRUPT，错误消息含数量及首个文件/行号，避免旧APP忽略integrity字段而只显示正常总数。维护人员可显式加allow_partial=1，获取部分有效事件和完整性诊断；不因此允许不完整导出。没有换行结尾的尾行暂不入索引，后续补齐后重新读取。

## 导出

GET `/api/v1/logs/export?format=jsonl`，或format=csv；可带相同设备/事件/时间过滤与snapshot。不带snapshot时导出当前完成索引的固定快照，包含当时已完成的行；处理期间追加的新行不混入本次文件。

超过16 MiB返回413 LOG_EXPORT_TOO_LARGE，提示缩小范围；不会以200返回截断文件。存在损坏行时默认409 LOG_DATA_CORRUPT，先查询定位，避免将缺失审计证据当成完整导出。未完成尾行会排除并在X-Log-Pending-Tail标明；正常文件仅剩写入中尾行不被当作中间损坏。

成功响应有Content-Disposition、Content-Length、X-Log-Snapshot、X-Log-Rows、X-Log-Pending-Tail。CSV保持UTF-8 BOM及detail字段。下载完成前客户端断开时清理临时文件和操作槽，不向已经开始的文件响应再混入JSON错误。

| 状态 | error_code | 处理 |
| --- | --- | --- |
| 400 | INVALID_ARGUMENT | 检查查询参数；与存储损坏区分 |
| 409 | LOG_DATA_CORRUPT | 查看files中的坏行位置，保留原始证据 |
| 409 | LOG_SNAPSHOT_EXPIRED | 文件已替换/截断，从第一页开始 |
| 413 | LOG_EXPORT_TOO_LARGE | 缩小设备或时间范围 |
| 503 | LOG_INDEX_BUILDING | 等待后台索引；只读GET可稍后重新查询 |
| 503 | LOG_BUSY | 等当前日志操作完成 |
| 503 | LOG_READ_FAILED | 检查文件读权限、磁盘与health.logs_index.failure_file |
| 503 | LOG_INDEX_UNAVAILABLE / LOG_QUERY_TIMEOUT | 检查索引状态或缩小范围 |

所有正常拒绝均通过现有JSON错误结构返回，带request_id，文件处理失败在发送200之前转换。日志索引失败不自动改变飞行控制权，原始异步审计失败保护规则保持有效。

## 测试

在backend目录运行 `python run_checks.py`；新增test_logs_bounds覆盖故障注入、快照、损坏定位、单页字节与导出上限。历史六项日志接口用例保留，前端32 MiB校验顺序仍应由B改为读取前/读取中限制；本次后端16 MiB上限使本服务不发送无限制的大文件。
