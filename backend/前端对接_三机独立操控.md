# 前端对接：三个操纵端各控一机，所有端观察三机

## 接入差异

所有端连接同一个 base URL，但使用不同 Token。原来的 `/api/session`、`/api/input` 和 `/api/cluster/select` 全局目标流程不适用；后端返回 DEPLOYMENT_MODE_MISMATCH，避免静默控制到主飞机。原 APP 需要修改接口绑定后再联调，本次后端包没有更改或重新编译 APK。

操作端凭据绑定 device_id/source，source 当前示例均为 app；只读凭据不绑定飞机。若以后接指环或语音，可在 independent_credentials.json 给对应设备增加独立 ring/voice 凭据，仍使用原三来源校验与中立切换；硬件联调需另行完成。

## 共同读取接口

| 方法与路径 | 内容 |
| --- | --- |
| GET /api/v1/capabilities | 模式、当前身份、自身设备、可写设备列表和路由 |
| GET /api/v1/devices | 三机目录、能力、每机 write_permitted 和 is_self |
| GET /api/v1/state | 三机统一位置、状态、姿态、告警、新鲜度 |
| GET /api/v1/events | SSE，event: state，data 为同结构三机快照，目标 25 Hz |
| GET /api/v1/devices/{id}/state | 指定飞机统一状态 |
| GET /api/v1/devices/{id}/events | 指定飞机统一状态 SSE |
| GET /api/health | 各实例健康及异步审计情况 |

以上读取对四种端均开放；读取本身不接管。只有拥有该设备写权限的来源可查询 `/api/v1/devices/{id}/commands/{source}/{command_id}`，只读端不能查询命令记录。

快照 `data.members` 包含三架，而不是只有当前操纵飞机。前端一条全机流即可同时画出本机和其他飞机，避免为地图重复订阅三条成员流。

关键字段：

| 字段 | UI 含义 |
| --- | --- |
| data.self_device_id | 本端绑定的飞机；只读端为 null |
| member.is_self | 是否使用本机图标突出显示 |
| member.device_id / boot_id / sequence | 设备标识、实例重启标识、动力学步号 |
| member.position.value.x/y/z | 同一仿真世界坐标，单位米 |
| member.position.validity | VALID / STALE / INVALID；失联不能继续画成实时运动 |
| member.velocity.value.x/y/z | 米每秒 |
| member.mode | HOLD / ACTIVE / PROTECTED |
| member.online / state_age_ms / alarms | 链路、数据年龄和告警 |
| member.control.write_permitted | 当前凭据有该设备写权限；不等于已经接管 |
| member.control.phase | 该机来源阶段；不能仅据此认定本地已获得有效会话 |
| member.control.has_control | 当前统一模型保留 null；APP 结合本地会话、epoch、归中和新鲜度判断是否就绪 |

三个实例有独立采样时刻；地图可以采用各成员最新位置，但应分别标注过期，不通过读取时间制造新的位置时间戳。电量和 GNSS 当前为 null，禁止填假数据。

## 操纵端握手与报文

以下以 pilot-2 控制 sim-drone-2 为例，所有请求都带：

```text
Authorization: Bearer demo-pilot-2-token-2026
Content-Type: application/json
```

1. 用户点击“申请本机控制”，POST `/api/v1/devices/sim-drone-2/session`：

```json
{"device_id":"sim-drone-2","cluster_id":"sim-cluster-1","user_initiated":true}
```

保存响应 data.session_id 和 data.control_epoch。替换同一来源会话会停止该飞机的旧操纵，另外两架不受影响；不要定时调用 session。连接丢失后不得自动恢复旧杆值。

2. 用户选择 APP 通路，POST `/api/v1/devices/sim-drone-2/switch`：

```json
{
  "device_id":"sim-drone-2","cluster_id":"sim-cluster-1",
  "session_id":"服务端返回的会话","control_epoch":"服务端返回的当前轮次",
  "command_sequence":0,"command_id":"switch-001",
  "sent_at_ms":1792460000000,"ttl_ms":500,
  "target_source":"app","user_initiated":true
}
```

时间戳示例必须换成当前 Unix 毫秒。switch 更新控制 epoch，使用本次响应中的新值；receipt.phase 为 WAITING_NEUTRAL 时只允许等待中立，不能直接运动。

3. 收到本端摇杆的实际归中采样，POST 同前缀 `/neutral`。使用递增 command_sequence、新 command_id、当前 session/epoch/时间戳，额外字段为 `axes:[0,0,0,0]`。成功后才允许新一次触摸产生运动。

4. 持续推杆时约每 50 ms POST `/api/v1/devices/sim-drone-2/input`：

```json
{
  "device_id":"sim-drone-2","cluster_id":"sim-cluster-1",
  "session_id":"当前会话","control_epoch":"当前轮次",
  "command_sequence":2,"sent_at_ms":1792460000000,"ttl_ms":500,
  "intent_sequence":0,"frame":"world","axes":[0.2,0,0,0]
}
```

axes 为 [-1,1] 的 X/Y/Z/YAW 归一化输入，后端按该机配置做死区、灵敏度与速度限制。world 为 X 前、Y 左、Z 上，正偏航绕 Z 轴逆时针；heading 为机头参考方向。默认地图使用固定世界朝向，不把屏幕左右直接当成世界 X。每条请求递增 command_sequence，不能只按运动请求递增；心跳、停止等共用本来源序号。

intent_sequence 在新的触摸/有效操纵事件开始时递增；超时或保护后不要循环递增 intent 来抢回控制。时间戳、TTL、epoch 和序号原样交给服务端校验。运动 POST 不自动重试或重放；ACK_OUTCOME_UNKNOWN 时查询离散命令或设备状态。

5. 松杆明确 POST `/stop`，携带新 command_id 和最新 epoch；停止和保护仍优先处理。已选中 APP 但没有运动时约每 100～200 ms 发 `/heartbeat`，只证明连接，不续期旧运动。解除保护、重新切换和归中由用户主动操作。离开操纵页面时 POST `/disconnect`，reason 为 APP_EXIT；突然断网由本机输入/监督超时保护兜底。

`/control` 支持旧速度报文 vx_m_s/vy_m_s/vz_m_s/yaw_rate_rad_s；`/protect`、`/resume`、`/cancel`、`/config`、输入适配等动作沿用现有参数和校验。路径前缀固定为本机，不再提供 selection_id 或调用 cluster/select。旧参数说明可参考“前端对接说明.md”，其中关于端口或全局选中的内容不适用于 independent 模式。

`/api/devices/{id}/*` 为相同写语义的兼容别名；其 state/events 返回旧成员原始结构，前端新地图应优先使用 v1 统一模型。

## 只读与越权响应

- 只读 Token 提交任何 POST：403 READ_ONLY。
- pilot-1 向 sim-drone-2 的路径写入：403 DEVICE_FORBIDDEN。
- 路由飞机与 body.device_id 不同：400 WRONG_DEVICE。
- 旧会话/轮次、过期报文、未归中，仍按原错误码拒绝；前端不能把所有 409 都解释成“只可观察”。
- 保护或失联只影响对应飞机；其他飞机仍可操纵和观察。异步审计发生全服务故障时会触发公共 AUDIT_UNAVAILABLE 保护，health 和快照公开原因。

## 前后端联合测试步骤

1. 同一局域网连接三个操纵端和一个只读端，各填对应 Token；四端都显示三个编号和初始位置。
2. 三个端分别主动接管并归中，同时小幅控制各自飞机，四端地图均应显示三个位置变化；本机图标正确，不允许改号操纵他机。
3. 只读端保留位置、模式、速度、在线及告警展示，操作事件即使强行发出也须被服务端拒绝。
4. 断开操纵端 1，飞机 1 应停止并进入保护；飞机 2/3 继续操纵，四端分别展示飞机 1 保护原因。
5. 操纵端 1 重连只先观察，主动处理保护、重新申请/切换/归中后再操纵，旧运动不能自动恢复。
6. 保留三端控制日志及四端状态刷新统计。后端本机 SSE 频率与手机 UI 实际刷新率分别测量，不互相代替。
