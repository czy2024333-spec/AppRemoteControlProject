# 前后端三机联调快速开始

## 1. 先确认工程

从 main 克隆仓库。前端 B 在 Android Studio 打开 VrxFusionRemote/；后端 A 在 VS Code 打开 backend/。前端依照其现有说明使用 JDK 17 / Android SDK 34；后端使用安装了 RotorPy 3.0.0 的 Python 环境。

## 2. 后端启动

在仓库根目录终端：

```powershell
cd backend
python run_backend.py --doctor
python run_backend.py --mode independent --host 0.0.0.0 --port 8765
```

新 Python 环境先安装 `python -m pip install -r core/requirements.txt`。自检 healthy=true 再启动。端口已占用时先辨认原进程，或统一改用其他端口；不要同时启动前端历史 server.py。

## 3. 四种端连接同一个地址

手机和电脑在同一局域网。APP 填 `http://电脑IPv4:8765`，手机的 localhost 是手机本身。

| 身份 | 开发样例 Token | 可写设备 | 读取范围 |
| --- | --- | --- | --- |
| 操纵端 1 | demo-pilot-1-token-2026 | sim-drone-1 | 三机 |
| 操纵端 2 | demo-pilot-2-token-2026 | sim-drone-2 | 三机 |
| 操纵端 3 | demo-pilot-3-token-2026 | sim-drone-3 | 三机 |
| 只读端 | demo-observer-token-2026 | 无 | 三机 |

以上是仓库公开的开发值，实际本机凭据可另存 *.local.json。原生 APP 的权限由 Token 绑定决定，不能靠改 UI 角色绕过；浏览器联调的 CORS 白名单另行配置。

先读取 GET /api/v1/capabilities，确认 deployment_mode=INDEPENDENT；GET /api/v1/state 或 SSE /api/v1/events 返回三机。按 [当前接口说明](../backend/前端对接_三机独立操控.md) 主动申请本机 session、切换并归中后再操纵。当前不调用全局 cluster/select，也不省略 device_id。

## 4. 联合检查

1. 三个操纵端和只读端均显示三个编号、位置、运行状态；操纵端突出自己的飞机。
2. 三端同时小幅运动，只改变自己绑定的飞机；四端均收到三机变化。
3. 只读 POST 与跨设备 POST 被服务端返回 403；只读展示仍可用。
4. 断开端 1，飞机 1 超时保护，飞机 2/3 保持可操纵；重连先观察，不自动恢复旧杆值。
5. 保留同一时段前后端版本、设备编号、测试时间、错误码、延迟和刷新统计。

## 5. 运行后端自测

在 backend/ 中：

```powershell
python run_checks.py
python run_independent_acceptance.py --seconds 60 --out results/my_trial_01
```

输出目录需要尚不存在。后一个命令自己开随机临时端口创建测试实例，不接管现场 8765。它验证本机 Python 控制和 SSE，不代替手机 UI、局域网、UE 或四小时稳定性验收。

发现卡顿时分别采指令生成、服务端接收、执行、回执和 APP 读取时间；不能把包年龄或单阶段耗时当端到端延迟，也不能通过放宽 TTL 或关闭保护获得通过。
