# v0.5：VSCode测试与手机局域网联调

## 1. 打开正确目录与选择Python

解压压缩包，在VSCode选择“文件 → 打开文件夹”，打开包含 `app_server.py`、`test_inputs.py`、`.vscode` 的 **三来源硬件适配_v0.5** 文件夹。

安装VSCode的Python及Python Debugger扩展。按 Ctrl+Shift+P，输入 `Python: Select Interpreter`，选择“输入解释器路径”，本机已有环境为：

```text
C:\Users\24107\.workbuddy-ai\binaries\python\envs\rotorpy-day1\Scripts\python.exe
```

关闭旧终端后新建终端，用 `python -c "import sys; print(sys.executable)"` 核对路径。若终端没有使用正确解释器，下面所有 `python` 都可替换成：

```powershell
& 'C:\Users\24107\.workbuddy-ai\binaries\python\envs\rotorpy-day1\Scripts\python.exe' -m unittest test_ctl test_inputs -v
```

前端同事在另一台电脑运行服务时需要自己的Python环境，并安装 `core/requirements.txt`。压缩包不含Python环境、供应商SDK或离线依赖。只运行手机APP的同事不需要安装Python，连接你的电脑即可。

## 2. 先验证软件逻辑

左侧选择“运行和调试”，上方选择 **CTL＋IN＋边界迟滞测试（35项）**，按 F5；也可在项目根目录终端运行：

```powershell
python -m unittest test_boundary test_ctl test_inputs -v
```

通过标准：结束显示 `Ran 35 tests` 和 `OK`，没有FAILED或ERROR。包括切换归中、旧输入拒绝、停止与超时、幂等、中文识别结果、低置信度过滤和危险动作确认。

接口日志中出现预期的400、409或501不代表测试失败，以最终测试结论为准；部分测试就是验证错误请求会被拒绝。首次正式测试前不修改 `control_config.json`。

## 3. 看一次完整切换演示

F5选择 **三来源完整切换演示（临时本机服务）**，或运行：

```powershell
python run_handover_demo.py
```

脚本自己启动临时服务，使用模拟来源通过真实HTTP完成 APP → 指环 → 语音 → APP，随后停止。无需先启动局域网服务。

打开 `results/handover/handover.png` 查看轨迹；打开同目录 `summary.json` 查看确认延迟和状态发布频率，`states.jsonl` 查看原始位置、姿态及来源，`events.json` 查看事件。一次演示结束后结果覆盖同名文件；包中已有记录是交付前结果，你运行后产生自己的结果。

这些是仿真数据和本机HTTP测量，不能作为手机实际刷新率或实物硬件联调通过的证明。没有UE三维手机画面。

## 4. 启动手机可访问的服务

停止正在运行的调试，再选择 **三来源局域网服务** 按 F5；或者：

```powershell
python app_server.py --host 0.0.0.0 --port 8765
```

保持这个终端运行。另开终端测试本机接口：

```powershell
Invoke-RestMethod -Uri 'http://127.0.0.1:8765/api/state' -Headers @{ Authorization = 'Bearer demo-app-token-2026' } | ConvertTo-Json -Depth 12
```

应收到JSON状态，含版本、控制来源及硬件待验收信息。若浏览器直接打开提示鉴权失败，原因是没有带Authorization头；使用上述命令或前端APP发送带头请求。

再运行 `ipconfig`，找到当前Wi-Fi或以太网的IPv4（不要用虚拟网卡地址）。假设为 `192.168.1.20`，手机APP服务地址填 `http://192.168.1.20:8765`。电脑与手机连接同一局域网，Windows防火墙如询问是否允许Python通信，允许当前可信的专用网络。不要关闭整个防火墙。

手机连不上时依次检查：服务仍在运行、本机请求成功、IPv4正确、同一局域网、防火墙允许该Python程序、路由器没有开启访客隔离。`0.0.0.0` 是服务监听地址，不能填到手机APP地址栏。

## 5. 前端按顺序验证

前端先读 `前端对接说明.md` 的公共字段和时序，再读 `IN接口补充说明.md` 的v0.5新增接口。来源凭据：

| 来源 | 联调Token |
|---|---|
| APP | demo-app-token-2026 |
| 指环适配器 | demo-ring-token-2026 |
| 语音适配器 | demo-voice-token-2026 |

每个来源用自己的Token建立 `/api/session`，每约100ms发送心跳；APP作为操作端，即使当前选中指环或语音也要继续心跳。手机和电脑时间同步，每条新请求使用新鲜时间戳及递增序号。

| 测试 | 操作与预期 |
|---|---|
| 状态读取 | APP读取 `/api/state`；订阅 `/api/events`，显示位置、姿态、当前来源和模式 |
| APP操纵 | 用户选择APP → `/api/switch` → 实际摇杆归中 `/api/neutral` → 新手势 `/api/input`；前后、左右、升降、偏航方向正确 |
| 切到指环 | 用户选择ring并归中，提交 `/api/ring-event` 新事件；旧APP运动输入拒绝，来源显示以服务反馈为准 |
| 切到语音 | 用户选择voice，清空旧识别结果并归中；提交新鲜 `/api/voice-result`，中文“前进”执行限时动作 |
| 过滤与确认 | 低置信度、无法识别、非最终结果返回IGNORED；“下降”等危险动作等待APP `/api/confirm`，确认前不执行该下降动作 |
| 停止与故障 | 测试停止、APP退出、当前外设断连、网络/输入超时；进入约定保持或保护并记录原因，重连不会恢复旧运动 |
| 恢复 | 保护后APP按规则 `/api/resume`，再重新选择来源、归中并产生新操作 |
| 重试 | 同一离散command_id重试不重复动作；同ID不同内容拒绝；旧轮次及旧序号拒绝 |

持续操纵建议每50ms发送新采样（20Hz），每次用户重新操纵增加intent_sequence，同一次手势更新保持不变。心跳不延长运动TTL。指环、语音尚无硬件时可用模拟事件验证上述协议，但必须标注软件测试。

前端记录“有效指令生成 → 收到统一服务确认”的耗时并计算P95，目标≤100ms；同时分别记录服务状态接收频率与APP真实渲染刷新频率，目标都≥20Hz。不能只用服务内部耗时或SSE频率证明手机指标达标。

## 6. 当前范围与反馈材料

起飞、降落、返航会返回 `501 TASK_NOT_SUPPORTED`，这些任务尚未实现。硬件兼容、驱动/SDK集成和真实硬件验收仍等待甲方设备及资料；供应商模块示例会明确报未实现，不能用它假装连接硬件。
