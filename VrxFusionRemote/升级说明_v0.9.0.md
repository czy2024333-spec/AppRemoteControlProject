# v0.9.0 三机独立操控升级说明

日期：2026-10-20。范围：Android 前端。用户提供的 v0.9 后端及 UE 代码未修改。

## 行为变化

1. 增加操纵端1、2、3及观察端四个公开联调预设；一个服务地址承载三架飞机。以服务返回的身份、设备绑定及权限为准，操纵端不能把观察到的其他成员变成写入目标。
2. 每端控制路由固定到绑定设备，所有会话、心跳、连续输入及安全动作使用该设备路由。连接时仅发现与观察，主动申请并完成归中握手后控制才生效。
3. 操纵页地图同时显示三机，本机黄色外圈，其他成员编号与颜色稳定；保留三机 XYZ 坐标行、固定朝向与当前位置近景切换。只读页增加地图下三机位置/状态紧凑汇总，详细信息可滚动查看。
4. 换身份先停止并释放原会话；停止后读取新的控制代次再断开，避免用旧代次释放失败。原会话释放未确认时阻止直接建立另一设备会话。清除旧飞机的轨迹、回执及局部状态。
5. 观察端只启动共享状态读取，不创建控制会话。其他成员保护、退出或失效不直接撤销本机控制；本机过期、权限和保护仍按原规则处理。
6. 沿用包名 `com.vrxfusion.remote.optimized`、应用名“旋翼遥控·优化版”及原发布签名，版本 900 / 0.9.0。继续使用同一操纵窗口，保留全屏画面、透明度、横竖屏与停止/保护提示。

## 接口与隔离

| 用途 | v0.9 路径 / 规则 |
|---|---|
| 能力与本端身份 | GET /api/v1/capabilities |
| 设备目录及写入标记 | GET /api/v1/devices |
| 全机快照 / 共享订阅 | GET /api/v1/state、GET /api/v1/events |
| 本机控制 | POST /api/v1/devices/{self_device_id}/{action} |
| 本机安全原始状态 | GET /api/devices/{self_device_id}/state、events |
| 连续输入及签名字段 | 设备/集群ID、会话、控制代次、序列号、时间戳及有效期 |
| 身份判断 | CONTROLLER 仅一个可写成员；OBSERVER 不绑定控制设备 |

本机额外安全订阅用于保留完整保护、边界迟滞及参数字段。共享三机地图只用一条全机订阅，不为三架分别开启控制会话。不再向旧的全局控制路径回退，也不调用全局集群选中接口来更换独立控制目标。

后端 v0.8 的显式 UNIFIED 能力解析和原有兼容路径仍保留；本版三机独立控制应使用 v0.9 INDEPENDENT 模式，不能通过旧全局接管实现。对 v0.8 的本次验证限于自动回归，不声明做了 v0.8 实机联调。

## 保留的控制保护

继续保留状态新鲜度校验、输入 TTL/心跳、权限与来源校验、主动接管及归中、停止/保护优先、离开操纵页清杆、连接代次隔离、丢失控制后禁止自动恢复。只对可重读 GET 做受限恢复，运动 POST 不自动重试，不重放旧指令。界面或 Token 预设不能绕过后端安全限制。

## 主要代码

- `unified/UnifiedModels.kt`、`UnifiedRepository.kt`：独立模式身份/目录/快照契约校验。
- `unified/ConnectionIdentity.kt`：四端公开开发预设。
- `unified/FlightGateway.kt`、`rotorpy/RotorPyClient.kt`：固定设备路由、观察/控制隔离及旧会话释放。
- `ui/FleetMarkers.kt`、`LandscapeControlScreen.kt`：全机位置、本机高亮、近景及坐标失效处理。
- `ui/UnifiedFleetScreen.kt`：三机只读地图、紧凑汇总及详情。
- `IndependentContractTest.kt`、`IndependentUiTest.kt`：四身份、路由隔离、原样后端联调及横竖屏检查。

## 范围及待现场确认

本版交付可分别操纵三机的 APP，不包含真实硬件驱动、语音识别算法、正式身份服务、UE 新程序或自主协同算法。UE 视频及手机/电脑摄像头设置沿用原功能，未将未接入画面标成在线。GNSS、电量等无真实数据时继续标注未接入。

请用指定三台 Android 手机及约定局域网完成最后联调。电脑回环测试结果不能代替手机 P95、APP 实际刷新、UE 帧率/时延或 4 小时稳定性验收。
