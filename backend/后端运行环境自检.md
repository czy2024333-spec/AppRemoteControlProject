# 后端运行环境自检

2026-11-12 · 方向五 · 独立三机模式

## 从哪里运行

在 VS Code 打开 `backend` 目录。用 `Python: Select Interpreter` 选已装项目依赖的 `drone-sim-backend` 解释器，再打开新终端。

```powershell
# 查看当前终端的解释器，确认版本和路径
python -c "import sys; print(sys.executable); print(sys.version.split()[0])"

# 本机回环自检
python run_backend.py --mode independent --doctor

# 模拟手机联调时的全网卡配置，检查实际要用的启动参数
python run_backend.py --mode independent --host 0.0.0.0 --doctor
$LASTEXITCODE
```

使用自定义凭据或日志目录时，将同一套 `--credentials` 和 `--results` 参数传给自检与正式启动。`--doctor` 读取并打印诊断 JSON 后退出。正式启动也会先执行相同检查。

| 输出 | 怎么看 |
| --- | --- |
| `healthy`、`checks` | 版本、依赖或配置检查失败时为 `false`，`--doctor` 退出码为 `2` |
| `warnings` | 退出码仍为 `0` 时也可以有告警，查看 `code` 和 `message` |
| `audit_storage` | 独立模式下查看生效的审计路径、文件大小和磁盘剩余字节 |
| `command_history` | 查看每来源会话的普通记录上限、安全回执上限和原始逐机状态展示的最近条数 |
| `command_queue` | 查看每机队列容量及 STOP、断连、PROTECT 可使用的预留位置 |

自检通过只表示启动前检查通过。端口监听、审计文件写权限、手机刷新率和实际仿真负载分别在启动和联调阶段验证。探针只读取磁盘信息，缺少结果目录时使用最近的现存上级目录。

## 解释器和短等待

- 程序自检的最低版本为 Python 3.11。Windows 上 CPython 从 3.11 起为 `time.sleep()` 使用等待计时器。程序启动时用单调时钟实测 31 次 `sleep(0.002)`，记录中位数和最大值。中位数超过 5 ms 时报告 `SLEEP_LATENCY_HIGH`。这是启动环境采样，实际步长和回执仍由三机负载试验确认。[Python time.sleep 文档](https://docs.python.org/3.13/library/time.html#time.sleep)
- 当前锁定的 NumPy `2.5.3` 和 SciPy `1.18.1` 的安装元数据要求 Python `>=3.12`。本机验证环境为 CPython `3.13.14`、RotorPy `3.0.0`。如果新建环境，按项目锁定依赖选择解释器。自检打印实际导入版本和 `requires_python`，便于定位装错环境。[项目依赖锁](core/requirements-lock.txt)

## 全网卡监听和示例凭据

当全网卡监听与已生效的公开示例 Token 同时出现时，自检报告 `PUBLIC_TOKENS_ON_ALL_INTERFACES`。自定义凭据文件里只要仍留有一个公开值，就会触发告警。输出只显示匹配数量。示例凭据与明文 HTTP 用于受控的局域网仿真联调，实际联调用独立的凭据文件并保存在仓库外。

## 审计文件与归档

独立模式默认将审计追加到 `results/independent_live/fleet_events.jsonl`。传入 `--results` 后，文件位于指定目录下。队列容量为 8192 条，正常约每 100 ms 刷新缓冲，持久化状态为 `BUFFERED_NO_FSYNC`。当前审计文件会随运行追加，自动轮转待实现。自检展示 `existing_audit_bytes` 和 `available_bytes`。剩余空间为 0 时报告 `AUDIT_VOLUME_FULL`，探测失败时报告 `AUDIT_STORAGE_UNVERIFIED`。

此前三控四观的优化组跑了三轮，每轮 60 秒。三轮审计文件分别为 864,974、864,731、864,915 字节，共约 59.9 条/秒，平均每条约 241 字节。按相同负载估算，审计原文件约 **49.5 MiB/小时**，四小时约 **198 MiB**。实际用量随操作频率变化，另需计入日志索引、导出及系统空间。[三轮负载条件摘要](../docs/validation/后端HUD_20261112_验证摘要.json)

需要归档时，在计划维护窗口结束操纵并正常停止后端，待审计排空后保留旧运行目录。下次启动使用新的 `--results` 目录。独立模式从运行目录中读取各机的 `control.json`，若需要沿用旧控制参数，应先确认并保留对应配置。原始 JSONL 用于留证，SQLite 索引可以重建。

## 命令历史上限与第三轮复测

普通离散命令按飞机、来源、会话保存在内存中，每个来源会话最多 1024 条。第三轮独立增加了最近 64 条安全动作回执。原始逐机状态最多带最近 8 条命令摘要。回执保留期间，用相同 ID 和内容重试会返回已有结果。替换同来源会话时旧命令查询记录会清除，已保存的审计日志可用于事后核对。

第二轮自检曾确认，新 STOP 和 PROTECT 会在历史满额时返回 `503 COMMAND_HISTORY_FULL`，飞机仍是 `ACTIVE`。第三轮修复后已用真实 HTTP 验证满额时能执行新的 STOP、PROTECT 和 DISCONNECT，且能查询新回执。修复前的复现见本机 `results/doctor/command-history-limit.json` · [第三轮自检](后端第三轮自检_安全命令历史.md)

归档与审计写入恢复仍需运行期方案。方向二的时间校验、链路参数和 STOP 轮次回读已单独补齐说明。[链路活性契约](后端链路活性契约.md)
