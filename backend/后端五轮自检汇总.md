# 后端五轮自检汇总

2026-11-13 · 后端 v0.9 · 独立三机模式

本汇总沿用《後端架構優化方向與現有問題.md》的 13 项编号和实施记录的轮次。PR #4 的 HUD 复审是基线，第一至第四轮已有本机验证记录。第五轮对应第 1 项审计就地恢复，目前待实施和复测。PR #4 的后端复审基线为 `c8f030e`。第一至第四轮的增量见同一 PR。[PR #4](https://github.com/czy2024333-spec/AppRemoteControlProject/pull/4)

## 基线 · HUD 与调度复审

Windows 下改用 `time.sleep()` 做仿真线程短等待。每种等待方式各测 3 轮，每轮 60 秒。三机步进间隔偏差 P99 的轮次中位数由 **15.12–16.81 ms** 降到 **0.96–1.06 ms**。改后控制 HTTP 往返 P95 为 **4.70–5.00 ms**，四路 SSE 约 **25 Hz**。[调度对照数据摘要](../docs/validation/后端HUD_20261112_验证摘要.json)

HUD 初版通过 125 项后端回归，PR #4 复审基线通过 131 项。共享发布线程异常或卡住时结束 SSE 并报告健康故障。STOP 的回执幂等纳入动作路径校验，同 ID 跨动作复用会被拒绝。同一发布序号的旧 `boundary_recovery` 和统一 `protection.recovery` 已验证一致。HUD 初版回归见本机 `results/checks-initial-hud/backend.txt` · [基线后端回归摘要](../docs/validation/后端HUD_20261112_验证摘要.json)

## 第一轮 · 链路活性契约（第 5–8 项）

- 会话 ACK 提供服务端接收和确认时刻。可选的 `client_sent_at_ms` 校验失败时返回 `CLOCK_SYNC_REQUIRED`，原会话仍有效。普通指令的错误详情可区分时间戳超前、到达时已过期和排队后过期。
- `link_policy` 公开状态频率、心跳间隔、过期阈值、续传帧数、`focus` 僚机频率、建议首帧期限及 TTL 等参数。`control.epoch_reason` 说明当前控制轮次为何变化。
- STOP 回执丢失时，先停发运动，再按原 ID 查回执并读取最新轮次。回归确认旧触摸意图换上新轮次后仍会被拒绝。
- **验证**　后端 135 项和固定 APP 版本的 26 项 JVM 回归通过。APP 已验证兼容解码，主动采用 `link_policy`、显示轮次原因及重连首帧计时仍待接入。[第一轮说明](后端链路活性契约.md) · [后端回归摘要](../docs/validation/后端三机_20261115_验证摘要.json)

## 第二轮 · 运行环境与存储自检（第 12、13 项）

- `--doctor` 检查 Python 最低版本、实际依赖和配置。程序最低版本为 3.11，当前锁定的 NumPy 和 SciPy 要求 3.12 起，本机使用 CPython 3.13.14。
- 启动时测 31 次 2 ms 短等待，中位数超过 5 ms 会告警。本机有效启动配置实测中位数为 **2.03–2.05 ms**。全网卡监听搭配公开示例 Token 会告警，输出只显示匹配数量。
- 审计自检可读文件体积和磁盘余量。既有三机负载折算原始审计约 **49.5 MiB/小时**。停机归档步骤已记录，自动轮转待实现。
- **验证**　后端 142 项通过。另复现单个会话累积 1024 条离散记录后，新 STOP 和 PROTECT 都返回 `503 COMMAND_HISTORY_FULL`，飞机仍可能处于 `ACTIVE`。[第二轮说明](后端运行环境自检.md) · 满额复现见本机 `results/doctor/command-history-limit.json` · [后端回归摘要](../docs/validation/后端三机_20261115_验证摘要.json)

## 第三轮 · 逐机安全命令回执（第 13 项）

- 每架飞机的每个来源会话保留 1024 条普通离散记录，另滚动保留最近 64 条 STOP、PROTECT、DISCONNECT 安全回执。普通历史满额时，符合权限、会话、序号和有效期校验的安全动作仍可执行。
- 真实 HTTP 复测确认满额时 STOP 进入 `HOLD`，PROTECT 进入 `PROTECTED`，断连回执为 `COMPLETED`。另一架飞机仍可操纵。已验证原 ID 幂等、旧序号拒绝及指环和语音的软件映射。
- **验证**　后端 148 项通过。另跑 60 秒本机三控四观，3570 条运动获回执，四路 SSE 均为 **25 Hz**。[第三轮说明](后端第三轮自检_安全命令历史.md) · [后端回归摘要](../docs/validation/后端三机_20261115_验证摘要.json) · 60 秒记录见本机 `results/independent-round3-60s/summary.json`

## 第四轮 · 队列满载与八路混合负载（第 11、13 项）

- 逐机执行队列的普通入队阈值为 128。STOP 和断连可再使用 8 个位置，PROTECT 和管理器内部屏障可使用最后 4 个位置，总容量 140。复测确认普通积压时安全动作可先执行，旧轮次或旧序号的运动仍被拒绝。对应预留也占满时仍返回 `QUEUE_FULL`。
- 旧集群用真实 HTTP 写满 2048 条普通历史后，批量 STOP 和 PROTECT 均成功下发至三架飞机。每个来源集群会话另存最近 64 个纯安全批次结果，含逐成员部分成功的回执。批量分发仍需取得管理器锁。旧集群满额复测见本机 `results/doctor/round4-after-cluster.json`
- 八路负载试验发现，使用相对结果路径时日志查询与导出会返回 400。已在打开结果目录时解析绝对路径。修复后 60 秒本机回环通过，3571 条运动和 1786 条心跳获回执，HTTP 往返 P95 为 **5.00–5.09 ms**，八路 SSE 各实收 **25 Hz**，60 次健康检查和 4 次日志导出均成功。2 号机步进间隔偏差最大为 **29.18 ms**，单轮数据不足以定位原因。[混合负载结果摘要](../docs/validation/后端三机_20261115_验证摘要.json)
- **验证**　后端 152 项、动力学 26 项通过。另有 1 项依赖历史实验产物的检查按默认条件跳过。以上频率与时延来自本机回环，手机 Wi-Fi、实际 UI 刷新和 UE 引擎端仍待验收。[第四轮说明](后端第四轮自检.md) · 后端回归见本机 `results/checks/backend.txt` · 动力学回归见本机 `results/checks/dynamics.txt`

## 第五轮 · 审计就地恢复（第 1 项，待做）

当前已通过故障注入确认，审计写失败时三机进入保护。现有恢复方式是修复存储问题后重启服务，再主动建立新控制会话。重启会重新初始化仿真实例。现有审计保护及重启回归见本机 `results/checks/backend.txt`

第五轮的验收目标是存储恢复后，审计写入能在进程内恢复，三架飞机保留现有仿真实例，继续处于保护或悬停。用户主动申请新会话，在满足解除条件时确认解除保护，再切换、归中并发起新运动。复测需覆盖持续写入失败、恢复探测、审计继续落盘和拒绝旧运动报文。
