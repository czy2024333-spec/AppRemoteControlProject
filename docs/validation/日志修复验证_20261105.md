# 日志三个问题修复验证 · 2026-11-05

基于 role-b-logs-export-1119 的 3525536，仅修改后端及文档。前端业务源码未改，不将本次记录当手机验收。

## 三项修复

1. 原查询/导出全量读 JSONL 改为后台有界分批 SQLite 索引。前台查询按索引分页，最大2000条、事件载荷约2 MiB；固定snapshot可用于下一页。导出先生成至多16 MiB临时文件，5秒构建预算，64 KiB分块发送，超限在发送200之前返回413。
2. 后台文件读失败返回503 LOG_READ_FAILED；索引不可用、建立中、繁忙和预算耗尽有明确错误码与request_id。下载开始后的socket取消单独收尾，不往文件响应混入错误JSON。
3. 坏JSON、错误时间戳、非有限值、非法UTF-8和超长行被统计并提供文件/行号/字节偏移。写入中的尾行待补全重读；损坏日志默认查询和导出均返回409，旧APP也能看到错误。维护人员可显式allow_partial=1查询部分结果及诊断，避免静默缺失。

## 回归

最终117项后端全部通过（原分支100项加17项新用例）；动力学26通过、1项可选历史输出检查跳过。新增用例包含实际HTTP 503、坏行与尾行、错误时间戳、读失败恢复、批次中途读取失败无丢行、快照分页与截断失效、页字节上限、导出超限、临时文件/索引数据库失败和并发槽释放。

## 十万行对照

使用与复查相同的100000行、23488890字节合成日志。首次后台索引约13.0秒单列，期间会提示建立中，不能把索引预热时间隐藏为查询加速。

查询limit=1的调用线程仅进行2次JSON解码（元数据及一条事件），Python分配追踪峰值21255字节；原实现解析十万行，追踪峰值110903003字节。无过滤大导出明确413；过滤后一万行导出文件2180000字节，追踪峰值88319字节。测量带tracemalloc，只统计Python分配，不含SQLite原生缓存或手机内存；不能当P95。

## 并发验证

本机60秒、三架在线/受控/传感器启用，三路HTTP操纵、四路SSE，并行日志查询和导出，附加十万行历史成员文件。没有通过修改TTL或保护阈值获得通过。

三路运动确认1187、1187、1188次，共3562次全部成功；P95约19.84、19.98、20.74 ms，最大约50.87 ms。四路SSE各1500帧，均25 Hz。日志查询成功282次，导出成功3次；另外13次操作得到预期的索引建立中/繁忙503，并非全程日志接口都即时可用。没有未预期日志错误，原审计关闭排空成功。

日志初次建索引与重负载时会暂时降低日志可用性，优先保留控制通路响应。索引磁盘线性增长、日志轮转和四小时运行未在本次完成；原地等长改写历史文件不受支持，需重启索引。当前16 MiB服务端上限不是前端读取前限额的替代；前端32 MiB校验顺序仍需B后续完善。
