2026-11-12 · 方向二 · 独立三机模式 · 对照 PR #4 的后端 `c8f030e` 和 Android `4dd149a`。[PR #4](https://github.com/czy2024333-spec/AppRemoteControlProject/pull/4)

## 会话校时与指令时效

会话成功响应的 `data.ack.server_received_at_ms`、`data.ack.confirmed_at_ms` 分别提供服务端接收和确认时刻，单位为 Unix 毫秒。PR #4 已用确认时间估计时钟偏差。校准后的客户端可在用户主动申请会话时提交 `client_sent_at_ms`。服务器在替换旧会话前检查该时间戳，超出窗口返回 `409 CLOCK_SYNC_REQUIRED` 和诊断信息，原会话继续有效。

普通指令仍通过 `sent_at_ms` 和 `ttl_ms` 校验。服务器先从 TTL 扣除接收时的报文年龄，再用单调时钟扣除服务器内耗时。超前容差为 50 ms。异常的大整数在参数校验阶段返回 `400 INVALID_ARGUMENT`，仿真线程继续处理后续合法请求。

| `error_detail.timing.reason` | 对应条件 |
| --- | --- |
| `CLIENT_TIME_AHEAD` | 时间戳超前超过容差。普通指令返回 `CLOCK_SKEW` |
| `EXPIRED_AT_RECEIPT` | 到达时已用完 TTL。普通指令返回 `EXPIRED_COMMAND` |
| `EXPIRED_WHILE_QUEUED` | 到达时仍有效，执行前已超过 TTL |
| `VOICE_DURATION_ELAPSED` | 语音动作在服务端等待期间已超过有效执行时长 |

`observed_age_ms` 同时包含传输耗时和客户端时钟偏差，`queue_age_ms` 由服务器单调时钟测得。时钟诊断触发后先校准，再由用户产生新操作。[独立模式接口定义](openapi_independent.json)

## 状态流参数

`GET /api/v1/capabilities` 的 `data.link_policy` 与原布尔能力表并列。统一契约为 `1.0`，已有 APP 可以读取原字段。

| 项目 | 默认值 |
| --- | ---: |
| 完整 SSE 目标频率 | 25 Hz |
| `focus` 其他成员摘要目标频率 | 10 Hz |
| 成员状态过期阈值 | 500 ms，取部署配置 |
| 空闲注释心跳间隔 | 1000 ms |
| 共享发布停滞阈值 | 1000 ms |
| 续传历史上限 | 50 帧 |
| 客户端建议的 SSE 读超时和首帧期限 | 各 3000 ms |
| 控制报文 TTL 上限 | 500 ms，逐机生效值由设备目录返回 |

APP 应分别计时首帧、网络读等待和状态过期。新状态用 `boot_id` 与 `sequence` 判断，注释心跳只维持链路。完整字段名、旧服务默认值及接入步骤见三机对接文档。[三机前端对接](前端对接_三机独立操控.md)

## 控制轮次与 STOP 回执

`control.epoch_reason` 记录当前轮次为什么产生。旧逐机状态对应 `control_epoch_reason`。例如 `STOP_APP`、`SESSION_REPLACED`、`EMERGENCY_APP`。同一轮次内的归中和运动会改变当前操作阶段，轮次原因继续描述轮次的来源。`SESSION_REPLACED` 只能确认同来源会话被替换。共享 Token 时，服务器没有区分手机的身份信息。

1. STOP 回执丢失时，APP 先停发运动。在重新申请会话前，按原 `command_id` 查询 `GET /api/v1/devices/{id}/commands/{source}/{command_id}`。
2. `phase=COMPLETED` 且 `completion_scope=SERVICE_APPLIED` 表示该 STOP 已在服务端执行。从最新的 `GET /api/v1/devices/{id}/state` 取得轮次、原因和模式。`HOLD` 或 `PROTECTED` 表示进入制动或保护，是否停稳取实际速度。
3. 恢复后由新的用户操作产生运动。使用旧轮次的请求返回 `STALE_EPOCH`，仅替换轮次仍使用旧触摸意图时返回 `RETIRED_INPUT`。
