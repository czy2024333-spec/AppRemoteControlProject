# 集群接口与前端对接 v0.6

## 版本与范围

本版增加集群管理器，默认sim-cluster-1下运行3架独立RotorPy实例，3架可同时受控，3架启用模拟位置/速度测量。此数量是当前电脑开发基线，不是任意硬件容量承诺。传感器是带独立随机误差的局部位置/速度仿真测量，不是GNSS、真实IMU或实物硬件。

多机启动使用cluster_server.py。app_server.py仍为原单机兼容入口；两者不能占用同一8765端口。集群服务不暴露旧/api/control等不带成员的旁路入口。APP需要按本文升级控制对象选择与请求封装；现有手机APK尚未完成本版现场验收。

后端保持X前、Y左、Z上，单位米。UE为每个device_id建立独立模型，读取各自position_m；按原三维协议转换厘米及Y方向，不能让所有状态覆盖同一个Actor。

## 鉴权与控制语义

继续使用APP、指环、语音各自Bearer Token，见原前端对接说明。APP管理集群、分组及控制对象；各来源可将自己的成员指令批量分发，但每架仍独立验证会话、来源、设备能力、归中、控制轮次、序号及TTL。集群编号和请求体中的source不能提升权限。

本期采用“同一集群只有一个当前控制对象”的明确规则：single选一架，group选一个分组，cluster选当前所有注册成员。对象切换需用户主动发起；已有对象时必须显式takeover=true。切换撤销旧selection_id并清除旧/新目标的来源选择、连续输入及待确认动作，随后每架重新执行来源选择和归中。控制对象选择不等于直接允许运动。

## 管理与状态接口

| 方法与路径 | 用途与附加字段 |
|---|---|
| POST /api/cluster/session | 建立本来源集群会话，body为{}，返回cluster_session_id |
| GET /api/cluster/state | 汇总成员、分组、当前控制对象、在线/受控/传感器数量和能力 |
| GET /api/cluster/events | 汇总SSE，目标25Hz |
| POST /api/cluster/register | 注册实例，member为完整独立配置，字段见cluster_config.json |
| POST /api/cluster/unregister | 成员退出并关闭实例，device_id；先保护并撤销旧控制对象 |
| POST /api/cluster/groups | 创建或替换分组，group_id、member_ids；成员需已注册 |
| POST /api/cluster/join | 指定device_id加入group_id |
| POST /api/cluster/leave | 指定device_id退出group_id；不注销实例 |
| POST /api/cluster/member-link | 联调链路状态上报，device_id、online(bool)；不是硬件链路自动发现 |
| POST /api/cluster/select | user_initiated=true、target_kind(single/group/cluster)，另带device_id或group_id；接管时takeover=true |
| POST /api/cluster/dispatch | 向当前完整目标成员集分发，selection_id、commands |
| GET /api/devices/{device_id}/state | 单成员状态，包含boundary_recovery和sensor_measurement |
| GET /api/devices/{device_id}/events | 单成员SSE，按成员state.stream_hz推送 |
| GET /api/devices/{device_id}/commands/{source}/{command_id} | 复用单机命令应答查询权限 |
| POST /api/devices/{device_id}/{原接口名} | 单机控制，额外携带cluster_id及selection_id；仍使用原成员公共字段 |

GET返回ok/data外壳，SSE每个data行直接是状态对象。状态中的selected_count为选中数量，active_count才是当前实际执行运动数量。状态汇总含各自sequence和simulation_time_s，并非同一物理时刻的原子快照。

## 集群请求公共字段

除建立会话外，管理POST与dispatch都带下列字段：

```json
{
  "cluster_id":"sim-cluster-1",
  "cluster_session_id":"建立集群会话返回的ID",
  "request_id":"本次操作的唯一UUID",
  "sequence":0,
  "sent_at_ms":1790000000000,
  "ttl_ms":500
}
```

时间戳必须首次生成请求时填写当前Unix毫秒，不能使用示例数字。sequence按集群来源会话严格递增；ttl_ms范围(0,500]，时钟超前最多50ms。排队及分发耗时扣除TTL。每架成员内部也保持自己的command_sequence、control_epoch、session_id及原始sent_at_ms/ttl_ms，不能共用一架的会话和轮次。

离散管理操作与离散批指令以request_id幂等；同ID同内容重试返回原应答，同ID不同内容拒绝。历史上限2048条，不静默淘汰；达到上限需停止并重建集群会话。连续/control、/input、/heartbeat批次用严格递增sequence防重复，不重试运动帧、不占离散历史；request_id用于日志关联。重放应答是历史快照，最新状态以GET/SSE为准。

## 批分发请求

在公共字段基础上增加selection_id及commands数组，每项为device_id、path、body。path使用原单机接口名，例如/api/session、/api/switch、/api/neutral、/api/input、/api/control、/api/voice-result。

```json
{
  "selection_id":"控制对象选择返回的ID",
  "commands":[
    {"device_id":"sim-drone-1","path":"/api/session","body":{}},
    {"device_id":"sim-drone-2","path":"/api/session","body":{}}
  ]
}
```

以上仅为附加字段示例，对应选中alpha组。必须精确列出当前选中成员集合，禁止漏成员、重复、额外广播。非/api/session请求的body必须含对应device_id及完整单机公共字段。各成员的请求可以不同，例如独立速度或配置。

响应status为APPLIED、PARTIAL或REJECTED，并返回succeeded、failed和逐成员results。HTTP200只表示获得汇总应答，不表示所有成员执行成功；前端必须检查results中的ok和error_code。成员并行分发，各自在自己的仿真线程验证执行，批操作非原子事务：某一架失败不回滚其他架已执行的动作。

同一批混合不同动作也会分别处理；本期参考客户端使用同一动作批次。API不得用“整个集群成功”覆盖PARTIAL，应提示具体失败成员。需要停止时发送新鲜停止/保护请求；不能自动重发失败运动帧。

## 推荐APP时序

1. 建立本来源集群会话，读取集群状态，在APP显示单机、分组和集群选项。
2. 用户选择目标，调用select取得selection_id和member_ids。由每个来源为对应成员建立独立/api/session。
3. APP批量/api/switch选择输入来源；目标来源每架提交新鲜/api/neutral归中采样。
4. 用户产生新意图后每约50ms发送一批运动采样。每架APP监督会话保持心跳，切到指环或语音后仍需APP心跳；心跳不延长运动TTL。
5. 对象切换后重新同步selection_id、各成员control_epoch，重新归中，禁止继续旧手势。
6. 失联或退出使当前selection_id失效，并保护旧控制对象；重连不恢复旧运动。重新选择对象后，先按各成员保护条件恢复，再选择来源、归中并产生新输入。

cluster_client.py提供可运行参考；run_cluster_demo.py展示三机→alpha组→单机的完整时序。真实指环归中及语音识别结果必须来自实际适配器，不能把演示的零轴作为硬件中立证明。

## 单机接管与失联

在集群或分组对象生效时，通过/devices/{id}/control单独操纵会得到CONTROL_CONFLICT。先由APP明确select(single,takeover=true)；旧集群请求将得到STALE_SELECTION。停止/保护/断连报告可跨控制对象，但仍必须通过成员会话、来源、序号及TTL校验。

监测到仿真线程退出、异常或状态超过lost_timeout_s未推进，成员标记LOST，并撤销当前控制对象。member-link用于联调时显式模拟断连，不能假称它验证了真实无线链路。恢复连接后需要人工重建控制流程，不接受旧selection_id。

## 配置与容量

cluster_config.json包含唯一编号、独立dynamics、control、sensors和state配置。默认3/3/3容量，超过配置数量拒绝；代码允许配置更高上限不代表已验证相应性能。运行期间注册、分组和成员增删是内存管理状态；重启按配置文件重新创建，不自动保存运行时注册表。正式部署需将认可的配置写入文件并随交付记录版本。

同一次服务运行中注销的device_id不复用，以免迟到指令误投新实例。每架动态控制参数仍走原受限/api/config校验，并独立保存在成员目录的control.json，重启时优先加载已保存值；无保存值时使用启动/注册配置。动力学和传感器配置由启动/注册配置决定，不通过普通操纵指令更改。

模拟测量字段与position_m动力学真值分开。每架有独立seed、采样率、位置/速度标准差和enabled标志；测量仅用于显示与联调，不反馈为动力学真值。离线状态data_quality=STALE，前端不能把缓存测量当成新数据。

## 预留协同接口

POST /api/cluster/task-split、/allocation、/formation、/cooperative-trajectory采用集群公共字段，另需task_id、member_ids、contract_version="0.1"、parameters对象。所有请求经过集群身份、APP权限、时效和成员存在性校验，然后返回501 COLLABORATION_NOT_IMPLEMENTED。

parameters预留任务定义、分配表、编队几何和协同航迹数据，详见collaboration_contracts.json。本期不实现自主拆分、任务分配、编队保持或协同避障，不能把接口存在或501应答认定为这些算法已完成。

## 日志关联

results/cluster_live/cluster_events.jsonl记录cluster_id、管理器boot_id、request_id、selection_id、device_id、member_boot_id及成员command_id/sequence，应答成功/失败可按request_id关联。各成员独立目录内control_events.jsonl保留原停止、保护和来源切换事件，其boot_id对应管理器日志的member_boot_id，可按device_id及时间继续核对。日志不输出Token。
