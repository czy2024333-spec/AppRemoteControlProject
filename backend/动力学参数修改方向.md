2026-11-21

本轮将《动力学参数(1).zip》的参数管理功能接入现有独立三机后端。评审对象包括原包源码、原包在隔离目录的运行结果和当前合并代码。原包 SHA256 为 `a8414155c2bef1ef6ae668b29461004f2341ef844faf26af127ac92ae1fd6faf`。

原包提供质量、惯量、最大总推力、电机响应时间、负载和飞行限幅的编辑与保存。包内 9 个文件的 GNSS/GPS 相关匹配为 0。原包的 5 项参数测试与 17 项验证通过，其中起飞、降落两项验证的是 `TASK_NOT_SUPPORTED` 拒绝行为。

## 已发现的问题与修改方向

| 问题 | 已确认的依据及影响 | 本轮修改方向 |
| --- | --- | --- |
| 直接覆盖旧服务端会破坏当前接入 | 隔离试验用原包覆盖后，导入当前三机模块时出现 `safety_action_path` 缺失。旧服务端还缺少当前快照与调度接口。 | 在当前服务端中合入参数功能，沿用现有校验、队列、快照、调度和三机路由。 |
| 修改参数把仿真时间归零 | 原包 `set_physics()` 调用 `reset()`。实测更新前时间 0.2 s，更新后为 0 s。GNSS 漂移和采样时钟、步号及回放时间关联会受影响。 | 先独立构建候选机体和控制器，提交时保留步号、位置姿态、速度、风场与边界原点。 |
| 仅调整限幅也触发模型重建 | 原包的参数写入路径每次都调用 `set_physics()`，原有副作用脚本只比较电机系数，无法发现时间和状态被重置。 | 比较质量、惯量、动力和负载，只有这些字段变化才构建模型。限幅更新单独提交，并验证时钟及测量序号连续。 |
| 保存失败前已改变模型 | 原包先替换模型再保存文件。保存失败后再次重建旧模型，期间的运动状态和时钟已受影响。 | 候选模型先构建并校验，文件成功保存后再提交内存。失败请求保留原模型、参数版本、状态和文件。 |
| 文件直接覆盖写入 | 原包直接以写模式打开正式 JSON 文件，写入中断可能留下半份文件。 | 在同目录写临时文件后原子替换，增加写入失败回归。 |
| 损坏文件回退通用 1 kg 默认值 | 原包读取损坏文件时返回通用默认值，与当前 0.03 kg 基准机型及各成员质量比例不同。 | 无文件时读取该成员基准参数。损坏或非法文件明确报错，要求修复配置后启动。兼容旧版直接保存参数对象的格式。 |
| 两套速度限幅会相互冲突 | 摇杆按 `control_config` 映射，动力学按另一套 limits 检查。物理上限缩小时，满杆可能生成超限指令。 | 归一化摇杆与语音使用两套上限的较小值，接口公开 `effective_control_limits`。 |
| 缺少参数变更的审计内容 | 原包仅保存当前版本和参数，独立审计中缺少变更字段与前后版本。 | 参数更新的控制轮次记录携带版本、字段前后值和更新来源，便于按设备关联。 |

| 新字段影响旧 HUD 样例 | 合并首轮全量检查发现，旧样例缺少参数数据时也被补入四个空字段，导致固定契约样例不一致。 | 参数字段按来源数据可选输出，旧样例继续匹配，新实例发布实际参数。 |

## 本轮采用的行为

参数按飞机分别保存到运行目录的 `{device_id}/dynamics_params.json`，默认完整位置为 `results/independent_live/{device_id}/dynamics_params.json`。每机具有独立版本号，缺少文件时版本为 1。写入沿用已有来源身份、设备绑定、会话、控制轮次、序列号、有效期与离散命令幂等检查。

参数修改由 APP 操纵来源提交，飞机须处于 `HOLD` 且没有待完成的来源切换。成功后更新该机版本并推进控制轮次，再次操纵需要按当前流程切换、归中并产生新输入。

新的高度区间需同时包含当前高度与配置的启动高度。这保证已保存的参数可以在相同启动配置下恢复。修改启动位置时应同步核对高度范围。

限速取值示例为动力学上限 0.2 m/s、APP 上限 0.5 m/s 时，有效上限为 0.2 m/s。动力学上限提高到 0.9 m/s、APP 上限仍为 0.5 m/s 时，有效上限为 0.5 m/s。当前控制配置校验的速度上界为 0.5 m/s，后续若需提高遥控指令速度，需要明确新的控制上限并同步验证。

参数文件保存最新版本，审计记录版本和字段差异。操作员指定旧版本的一键回滚可作为后续接口设计。

## 参数配置的阶段建议

按当前纯仿真、三机控制、GNSS 和 UE 联调的目标，建议保留质量配置能力，惯量先采用机型固定值。在线编辑质量与惯量的优先级低于控制链路、测量连续性和画面联调，具体前端开放范围可按验收目标确定。

| 参数 | 作用及适用实验 | 当前建议 |
| --- | --- | --- |
| 质量 | 影响悬停推力和相同外力下的加速度，用于比较机型和负载。 | 保留可配置能力，使用机型资料或明确实验条件确定数值，默认使用基准机型。 |
| 惯量 | 影响滚转、俯仰和偏航响应，与质量在机体上的分布有关。 | 先使用机型预设；开展姿态控制、偏心载荷或模型误差实验时，再开放高级编辑。 |

APP 的日常入口建议优先提供“选择机型”和“设置负载”，原始质量、惯量及动力参数放在高级配置中。机型预设应包含相互匹配的质量、惯量、机体几何和动力参数，便于重复实验和比较三机结果。质量和惯量的编辑沿用前文的悬停提交、版本管理与审计流程。

当前模型构建时，机体与控制器使用同一套参数，并按质量和最大推力重新计算电机系数。修改质量后仍能稳定悬停，验证的是已知模型参数下的闭环运行。若后续研究未知负载或模型误差下的抗扰能力，需要分别配置机体实际参数与控制器估计参数，并明确载荷变化时刻及控制器是否重新整定。[模型与控制器构建](core/run_lab.py)

## 接口方向

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/v1/devices/{device_id}/params` | 查询指定飞机的参数、版本、来源和有效控制限速。授权观察端也可读取。 |
| `POST /api/v1/devices/{device_id}/params` | 提交 `params_version`、`patch` 与完整控制报文头，修改绑定设备。 |
| `GET/POST /api/devices/{device_id}/params` | 独立模式的原逐机路由。 |
| `GET/POST /api/params` | 单机兼容服务的参数接口。 |

统一状态与原始状态发布参数版本和参数对象，设备目录补充参数能力与读取路径。OpenAPI 和前端对接说明随代码更新。

查询返回 `data.params_version`、`data.dynamics_params`、`data.dynamics_params_origin` 和 `data.effective_control_limits`。状态流中的版本字段名为 `dynamics_params_version`。参数来源取 `BASELINE`、`FILE` 或 `MEMORY`。

以下示例在运行后端后，从后端目录的项目解释器执行。它将 1 号机的物理水平限速调为 0.2 m/s，并按当前规则重新建立操纵意图。

```python
from independent_client import IndependentClient

client = IndependentClient("sim-drone-1", "demo-pilot-1-token-2026")
try:
    client.open_session()
    current = client.request("/api/v1/devices/sim-drone-1/params")
    changed = client.discrete(
        "/api/params",
        params_version=current["params_version"],
        patch={"limits": {"max_horizontal_speed_m_s": 0.2}},
    )
    print(changed["params_version"])
    client.switch("app")
    client.neutral()
    client.begin_intent()
    client.stop()
finally:
    client.close()
```

直接发送 HTTP 时，写入请求须包括 `device_id`、`cluster_id`、`session_id`、`control_epoch`、`command_sequence`、`command_id`、`sent_at_ms`、`ttl_ms`、`params_version` 和 `patch`。主要参数错误码为 `INVALID_PARAMS`、`PARAM_OUT_OF_RANGE`、`PARAMS_VERSION_CONFLICT`、`PARAMS_SAVE_FAILED`。来源、权限、时效和保护错误沿用现有错误码。

## 对质量与惯量开发范围的建议

整体影响集中在机体模型、控制器构建、参数持久化和发布字段。现有三机混合负载和回归通过，说明功能接入与本机运行性能已有验证。物理参数与机型的一致性还需单独验证。

基准动力学本身需要质量与惯量。建议本期采用固定、经过验证的机型配置，APP 提供只读展示，将任意编辑和运行时重建延后。速度限幅与灵敏度配置继续按已有验证范围使用。

待有实际机型的质量、惯量、动力和负载资料后，再按机型建立参数档案，逐项验证悬停、转向、抗扰及稳定性。若验收明确要求编辑质量或惯量，可优先提供受控机型档案和离线切换，并补齐参数一致性验证。

当前实现仍支持 HOLD 状态下的参数写入。本次复查补充了耦合问题及建议，参数冻结策略需在确定开发范围后落实。
