## 原样 v0.9 后端三机 / 四端联调

环境：Windows、JDK 17、Android 客户端同一控制代码在 JVM 中运行；原后端三个仿真实例，临时本机回环端口。三路操纵端加一路观察端同时连接，三机连续操纵 60 秒。

| 项目 | 结果 |
|---|---|
| 四端发现与观察 | 均收到三机快照，初连不自动接管 |
| 三机独立持续控制 | 60 秒期间三端保持有效就绪，各机位置分别变化 |
| 本机与其他飞机观察 | 四端均能读取三个新鲜成员；四端接收频率断言均 ≥20Hz |
| 单机保护、退出 | 1号保护及释放会话后，2/3号保持各自有效操纵 |
| 观察端及端1越权写2号 | 后端均返回 HTTP 403，另外两机控制不受影响 |
| 2/3号归中 | 归中后回 HOLD，保留各自正常会话 |
| 审计收尾 | 队列成功排空，4671 条接收/写入，0 拒绝、0 残留 |

客户端采样汇总如下，原始 JSON、JUnit 与后端事件记录见交付包“验证记录”：

| 操纵端 | 成功确认数 | 确认失败/取消计数 | 状态接收 Hz | 确认 P95 桶上界 ms |
|---|---:|---:|---:|---:|
| sim-drone-1 | 979 | 0 | 24.96 | 25 |
| sim-drone-2 | 985 | 1 | 25.00 | 24 |
| sim-drone-3 | 986 | 0 | 24.95 | 25 |

失败计数也包含归中/释放时取消的在途请求；本次汇总没有细分这一条计数的原因，不能将全部请求描述为零失败。60 秒控制阶段的有效会话检查通过，未观察到持续控制失效。P95 为客户端“指令生成至服务接收确认”的桶上界，不含语音识别或动力学执行，也不是手机局域网性能结论。记录的 Hz 为状态接收率，不冒充手机实际绘制刷新率。

`audit-status.json` 在服务关闭后采集，因此 `healthy=false`；同记录 `failure=null`、`drained=true`、`pending=0`、`accepted=written=4671`、`rejected=0`。不能将关闭后的布尔值当成运行中审计故障。后端审计为缓冲写入（BUFFERED_NO_FSYNC），本报告不声明每条事件已同步落盘。
