# 后端状态回放与 UE 接口整合说明

2026-11-21 · 后端 v0.9 · 独立三机模式 · 统一读取契约 1.0

本轮将角色 B 源码包中的状态录制、历史查询、文件导出和 UE 集群状态订阅合入当前后端。启动入口为本目录的 `run_backend.py --mode independent`。

来源包为 `角色B-1126迁移回放与UE联调源码包-20261121.zip`，SHA256 为 `ac696ae749820c24478b31825f546e788cd8fae749bb966e017d29dafc789125`。整合使用 11 月 20 日 GNSS 优化后的本地后端作为基础。

## 新增功能

| 功能 | 使用方式与行为 |
| --- | --- |
| 三机状态录制 | 独立模式启动后，共享状态发布线程将三机真值按平均 10 Hz 抽稀，交给独立的异步文件队列。每个录制时刻为每架飞机保存一条样本。 |
| 历史查询 | `GET /api/v1/replay/frames` 按设备和录制时间过滤，支持固定快照分页。 |
| 回放导出 | `GET /api/v1/replay/export` 返回 JSONL，沿用有界索引和 16 MiB 导出上限。 |
| UE 实时订阅 | `GET /api/v1/ue/events` 一条 SSE 流提供三架飞机的平铺三维状态，目标 25 Hz。 |
| 能力发现 | `/api/v1/capabilities` 提供 `replay_schema`、三个新路由和 `state_replay`、`replay_export`、`ue_state_stream` 布尔能力。 |
| 录制故障反馈 | `/api/health` 的 `data.replay` 返回录制健康、失败原因、队列和写入计数。录制失败后停止采样，查询注明完整性，导出返回明确错误。 |

共享发布线程按当前调度相位取三机快照。APP 统一状态、逐机 HUD、UE 平铺状态和回放采样均从这些快照构建。GNSS 继续使用各成员独立的采样与误差模型。

## 接口调用

在后端目录选择 `drone-sim-backend` 解释器后启动。

```powershell
python run_backend.py --mode independent --host 0.0.0.0 --port 8765
```

以下命令在后端电脑的 PowerShell 中执行。测试凭据取自随代码提供的公开开发配置，实际部署按自己的凭据替换。

```powershell
$backendUrl = 'http://127.0.0.1:8765'
$requestHeaders = @{ Authorization = 'Bearer demo-observer-token-2026' }
Invoke-RestMethod -Uri "$backendUrl/api/v1/capabilities" -Headers $requestHeaders
Invoke-RestMethod -Uri "$backendUrl/api/v1/replay/frames?device_id=sim-drone-1&limit=100&offset=0" -Headers $requestHeaders
Invoke-WebRequest -Uri "$backendUrl/api/v1/replay/export?device_id=sim-drone-1" -Headers $requestHeaders -OutFile 'replay-drone-1.jsonl'
```

手机和 UE 同处局域网时，服务地址使用后端电脑的 IPv4。UE 的 SSE 请求携带 `Authorization: Bearer <token>`，订阅 `/api/v1/ue/events`。操纵和只读凭据都能读取三个新接口，控制命令仍使用绑定设备的控制路由。

按 B 包交付的 C 侧配置约定，UE 设置 `EndpointMode=Cluster`、`ClusterEventsPath=/api/v1/ue/events`、`ClusterHealthPath=/api/health`、`DynamicsFeed=Network`、`bLocalCoreDemoMotion=False` 和 `MaxSpawnedMembers=3`，并填入有效开发凭据。

默认录制文件为 `results/independent_live/replay/state_frames.jsonl`。通过 `--results` 指定其他运行目录时，回放文件写入该目录下的 `replay/`。

### 查询与分页

查询支持 `device_id`、`since_ms`、`until_ms`、`snapshot`、`offset`、`limit` 和 `allow_partial`。时间筛选使用录制时刻的 Unix 毫秒。缺省每页 200 条，单页最多 2000 条，偏移上限 100000。损坏文件默认明确报错，`allow_partial=1` 用于检查可读记录及损坏位置。

响应位于 `data.samples`。每次查询返回 `snapshot`、`next_offset`、`has_more` 和 `integrity`。继续下一页时传回同一 `snapshot`，避免新录制记录改变已查询范围。

分页和 `total` 按逐机样本计数。三机录制 100 个时刻通常产生 300 条样本，同一时刻的三个成员可能跨页。消费端使用 `boot_id + frame_sequence` 归并一帧，使用完整 `device_id` 区分成员。迁移原始 JSONL 到另一运行目录的 `replay/` 后，后台索引可重建历史查询。新启动的记录携带新的 `boot_id`。

固定快照还可能截在最新一帧的成员之间。本轮运行中一次导出返回 211 条成员样本，末帧仅包含部分成员。`integrity.complete` 描述文件读取与索引的完整性。播放器应先归并成员，齐备后再播放整帧，并在下一次查询新快照时合入尚缺的成员。

### UE 字段与坐标

实时流的顶层包含 `cluster_id`、`boot_id`、`selection` 和 `members`。每个成员携带 `device_id`、`sequence`、`simulation_time_s`、`server_time_ms`、`position_m`、`velocity_m_s`、`quaternion_xyzw`、`angular_velocity_body_rad_s`、`online`、`state_age_ms`、`data_quality`、`link_status`、`control_epoch` 和保护原因。

后端实时坐标采用 X 向前、Y 向左、Z 向上，位置单位为米。UE 接收实时原字段后执行一次坐标转换。回放样本同时提供 `source` 米制字段和已经转换的 `ue` 字段，消费 `ue` 时直接使用该结果。

| 转换项 | 仿真到 UE |
| --- | --- |
| 位置 | `(x, y, z) → (100x, -100y, 100z)`，单位 cm |
| 线速度 | `(vx, vy, vz) → (100vx, -100vy, 100vz)`，单位 cm/s |
| 四元数 | `(qx, qy, qz, qw) → (-qx, qy, -qz, qw)`，XYZW、体轴到世界 |
| 体轴角速度 | `(wx, wy, wz) → (-wx, wy, -wz)`，单位 rad/s |

`ue.flags` 的位 0、1、2 分别表示状态、位置和姿态有效，位 3 表示仿真真值。在线成员通常为 15，失联成员保留真值来源位并输出 8。UE 游戏线程注入快照时填写自己的 `WallClockSec`。

常规编号 `sim-drone-1` 至 `sim-drone-3` 对应 `ue_device_id=1` 至 `3`。数字后缀缺失、超出 Int32 或与其他成员重复时，`ue_device_id=null`，完整字符串编号仍可用于关联。

SSE 事件按 `event`、`data`、`id`、空行输出。UE 使用独立的续传 ID 前缀。跨 APP/UE 接口复用旧 ID 时发送重同步后的最新帧。相同接口的短时续传沿用当前有界历史。
