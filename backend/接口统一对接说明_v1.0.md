# 后端统一接口 v1.0：已实现对接约定

日期：2026-10-19。实现版本：后端0.8.0；对照前端v0.7.8及《统一接口设计v1.0评审稿》。本包只修改后端。

## 1. 当前范围

一个服务地址同时提供原单机0.5、原集群0.6以及新增v1发现/只读模型。旧HTTP/SSE路径和请求体保持兼容，前端可以先继续运行，再逐步迁移状态仓库。没有新增旧WebSocket或视频服务，也没有把前端内部MotionIntent示例当成可发送协议。

新增v1写意图转换、FlightGateway前端实现、正式账号/角色、UE媒体及硬件接入不属于本次已完成范围。`capabilities.unified_intent_write=false`，向未开放的v1写路径POST返回501/NOT_SUPPORTED，不会静默控制设备。

## 2. 同一地址与路由

所有下列路径使用同一个主机与端口，默认8765，携带`Authorization: Bearer <来源Token>`。默认APP Token仍为`demo-app-token-2026`；指环、语音各用原独立Token。不要把Token放到URL。

| 用途 | 方法与路径 | 状态 |
|---|---|---|
| 能力/部署/认证方式发现 | GET `/api/v1/capabilities` | 新增，实际能力 |
| 设备目录 | GET `/api/v1/devices` | 新增，来自运行实例 |
| 全部成员统一状态 | GET `/api/v1/state` | 新增 |
| 全部成员统一SSE | GET `/api/v1/events` | 新增，event: state |
| 指定设备统一状态/SSE | GET `/api/v1/devices/{id}/state`、`/events` | 新增 |
| 指定设备统一命令回执 | GET `/api/v1/devices/{id}/commands/{source}/{command_id}` | 新增；路径source用app/ring/voice |
| 健康 | GET `/api/health` | 统一进程及成员健康 |
| 原单机状态/SSE | GET `/api/state`、`/api/events` | 固定主设备，默认sim-drone-1 |
| 原单机命令查询 | GET `/api/commands/{source}/{command_id}` | 主设备原始回执 |
| 原单机写控制 | POST `/api/session`、`/switch`、`/neutral`、`/input`、`/control`、`/stop`、`/protect`、`/resume`等 | 原请求体与安全流程 |
| 原集群状态/SSE | GET `/api/cluster/state`、`/api/cluster/events` | 与单机来自同一批实例 |
| 原集群管理/分发 | POST `/api/cluster/session`、`/select`、`/dispatch`等 | 保留原0.6协议 |
| 原成员控制 | POST `/api/devices/{id}/{action}` | 原集群/目标/成员会话校验 |

单机、集群原详细请求体分别见`openapi.json`、`openapi_cluster.json`；新增只读路径见`openapi_unified.json`。SSE数据直接为状态对象，普通JSON响应为`{ok,data,request_id}`。

## 3. 旧APP兼容规则

1. GET状态、订阅SSE和能力发现均不会创建会话、选择目标或接管。
2. 只有APP明确POST旧`/api/session`时，若无控制对象，后端才预留固定主设备作为单机目标。随后仍需原`switch→neutral→input`，会话不等于可运动。
3. 如果已有小组/集群目标，旧单机申请返回CONTROL_CONFLICT，不自动抢占。用户须通过集群协议明确选择/接管。
4. 主设备由启动参数`--primary-device`固定；运行中主设备退出时，旧入口返回MEMBER_NOT_FOUND，不改指向其他飞机。
5. 兼容层仅补齐路由所需cluster_id/selection_id，不补会话、epoch、序号、TTL或中立输入。客户端显式携带的冲突标识会被拒绝。
6. 单机与集群控制互斥由同一个管理器仲裁。目标变更使旧会话/控制轮次失效，旧运动不能用于新目标。

本次APP集群界面仍只是监控；后端已有集群控制能力不代表APP已接入集群操纵。

## 4. 统一状态与空值

- 坐标：世界X参考前方、Y参考左方、Z向上；米、m/s、rad/s；四元数xyzw、机体到世界。角速度字段明确为BODY参考系。
- 固定轨迹图：右方向−Y，上方向+X；APP右杆默认WORLD。兼容HTTP请求继续使用小写`frame=world/heading`、四轴列表`axes`，不是新的大写枚举或axes_normalized对象。
- 每个成员含真实boot_id及原动力学sequence；只有真实步进/注册修订变化才发新SSE，不用GET次数、刷新时间戳或重复帧续命。
- 位置、速度、姿态标明SIM_TRUTH；本地位置/速度噪声测量标明SIM_MEASUREMENT。它不是GNSS，不输出伪造经纬度。
- 未接入电量、GNSS为value=null、validity=NOT_CONNECTED；缺失/非法向量为null/INVALID，失联的最后有效值为STALE；不补0或100%。
- v1来源枚举用APP/RING/VOICE；原协议继续使用app/ring/voice。设备ID始终一致。
- 状态中的control.has_control=null：来源Token观察请求不携带用户租约身份，不能由“当前来源是APP”推断这个连接持有控制权。前端应按自己的已确认会话/epoch/握手回执建立ControlLease。
- takeoff、land、return_home、自主协同和UE视频未实现，目录能力明确为false；任务NOT_SUPPORTED，UE视频NOT_CONNECTED。
- 目录附每设备生效的控制限值、通路启用配置和config_version；全局500ms仅是协议硬上限，发送TTL必须服从设备当前input_ttl_ms。

`authentication.mode=DEVELOPMENT_SOURCE_TOKEN`，user_id/role/有效期为null，formal_user_roles=false。保留来源权限与控制权验证，不伪装成正式登录、管理员或真实用户租约。

## 5. 回执与错误

旧POST响应保留原data，在顶层新增`receipt`。v1命令查询直接返回归一化receipt。不要用HTTP200推断设备已物理完成。

- 原APPLIED/COMPLETED映射COMPLETED时，completion_scope只能为SERVICE_APPLIED，表示服务已应用动作；不表示飞机已停稳或已完成返航。
- WAITING_NEUTRAL、WAITING_CONFIRMATION、EXECUTING、CANCELLED、TIMED_OUT等保持阶段；语义未知的成功响应只映射RECEIVED。
- 集群逐成员校验，PARTIAL明确保留，附成功/失败数量及成员明细，不改成全体COMPLETED，不宣称事务回滚。
- command_id幂等规则保留：相同ID相同动作查询/返回旧结果，变更动作拒绝；运动指令不重试。
- 新增error_detail含code、message_key、raw_code、retry_policy、设备/命令ID；原error/error_code保留。ACK_OUTCOME_UNKNOWN映射OUTCOME_UNKNOWN，要求按原command_id查询，不能换ID自动重发。

现有服务尚不报告独立DEVICE_ACTION_COMPLETED、语音识别耗时或模型执行耗时；相关字段不得由适配器自行推断。

## 6. 安全与并发

停止、保护和断开成员入口不等待普通分发占用的管理器锁；保护前读取主设备epoch也不被该锁阻塞。安全动作仍通过成员来源、会话、设备、序号及TTL校验，保护在成员执行器中优先。

保护不因普通停止或旧运动而解除；目标切换清除输入，新来源必须真实归中。断网、输入过期、失联及旧epoch规则不放宽。APP主动取消HTTP导致的预期连接重置按断连处理，不再打印为服务线程崩溃。

## 7. 前端本轮对接顺序

1. 连接后先GET capabilities，根据实际模式/能力显示功能；保持原来源Token。
2. 设备目录用v1/devices，状态仓库统一映射v1/state或v1/events，保留空值、有效性、boot_id和sequence。
3. 已运行的单机控制继续生成原0.5请求；新增后端地址即可共用集群监控，无需切换服务进程。
4. 把POST顶层receipt及查询结果映射统一CommandReceipt，保留SERVICE_APPLIED和PARTIAL；不要把内部MotionIntent JSON直接POST。
5. 集群实际操纵、统一写模型、正式身份权限另行冻结请求协议后接入；前端不能因目录显示后端支持而自动申请或广播控制。

视频继续采用独立媒体配置并通过device_id关联，本后端没有伪造UE流地址。P95与APP刷新率仍需实际手机局域网联合验收，开发机短时回归不能替代4小时或硬件验收。
